## Overview

Nuxt UI components never read a palette shade. Their classes read semantic utilities like `bg-soft` or `text-accent-default`, and each utility reads a `--ui-*` CSS variable. Point those variables at the tokens of your design system and every component follows, in light and dark mode.

Follow the steps below in order. Each one changes more than the next, so most of a design system is in place before you reach the [app config](#app-config), which is for what the variables can't express.

::tip
The `nuxt-ui-design-system` [skill](/docs/getting-started/ai/skills#design-system) gives an AI agent this procedure: it reads your tokens from CSS, a Tailwind CSS config, a design tokens JSON file or Figma, and maps them onto these variables.
::

## Token contract

The variables on this page and the utilities they feed are public API from Nuxt UI 5.0. Renaming or removing one is a breaking change that goes through the [migration guide](/docs/getting-started/migration). Their default values aren't: a minor version can pick another shade or another mix.

Set them on `:root` and `.dark`, outside `@layer theme`, except the `--ui-control-*` variables components set in their `size` variants, all of them but `--ui-control-text-step`, see [Control sizing](#control-sizing). The defaults sit in `@layer base` at zero specificity, so an unlayered rule or one in `@layer base` wins.

::note
Variables this page doesn't list, like `--ui-accent-bg-soft`, `--ui-layer-bg-soft` or `--ui-highlight`, are set by the components and can change in any version. Set the token or the [per-color role](#per-color-roles) instead.
::

### Colors

| Variable | Read by | Light | Dark |
| --- | --- | --- | --- |
| `--ui-color-<color>-50` to `-950` | The shade utilities, like `bg-primary-600`, and the alias | The palette of the [`@nuxt/ui/colors`](/docs/getting-started/theme/design-system#configure-colors) plugin | Same |
| `--ui-<color>` | `bg-primary`, `text-primary`, and the `solid` variant of every component in that `color` | Shade `500`, `900` for `neutral` | Shade `400`, `50` for `neutral` |
| `--ui-accent` | Every `accent` utility, set by the `color` prop | The component's color | Same |

`<color>` is one of the seven aliases or a color you [add](#added-colors).

### Text

| Variable | Utility | Read by | Light | Dark |
| --- | --- | --- | --- | --- |
| `--ui-text-faint` | `text-faint` | Placeholders, field icons, menu item icons | `neutral-400` | `neutral-500` |
| `--ui-text-muted` | `text-muted` | Descriptions, help text, inactive tabs and links | `neutral-500` | `neutral-400` |
| `--ui-text-default` | `text-default` | The body, labels, the text of menus | `neutral-700` | `neutral-200` |
| `--ui-text-strong` | `text-strong` | Titles, field values, the selected item | `neutral-900` | `white` |
| `--ui-text-contrast` | `text-contrast` | Text on `bg-neutral` and on solid colors | `white` | `neutral-900` |

### Background

| Variable | Utility | Read by | Light | Dark |
| --- | --- | --- | --- | --- |
| `--ui-bg-default` | `bg-default` | The page, cards, the `outline` variant | `white` | `neutral-900` |
| `--ui-bg-tint` | `bg-tint` | Hovered rows and items, table heads | Unset, `bg-soft` at 50% | Same |
| `--ui-bg-soft` | `bg-soft` | Highlighted items, the `soft` neutral variant | `neutral-100` | `neutral-800` |
| `--ui-bg-strong` | `bg-strong` | Tracks of Progress, Slider and Switch | `neutral-200` | `neutral-700` |
| `--ui-bg-backdrop` | `bg-backdrop` | Behind a Modal, a Slideover or a Drawer | `bg-soft` at 75%, `bg-default` at 75% once `--ui-bg-overlay` is set | Same |
| `--ui-bg-overlay` | `bg-overlay` | Menus, popovers, tooltips, modals, toasts | Unset, `bg-default` | Same |
| `--ui-overlay-bg-soft`, `--ui-overlay-bg-strong` | `bg-soft`, `bg-strong` on a floating layer | Highlighted items in a menu | Unset, one step up from the page | Same |
| `--ui-neutral-bg-hover` | `bg-neutral-hover` | A hovered `bg-neutral` surface | Unset, `--ui-neutral` at 90% | Same |

An unset variable is a hook: its utility holds the default, so `var(--ui-bg-tint)` in your own CSS resolves to nothing. Use the utility instead.

### Border

| Variable | Utility | Read by | Light | Dark |
| --- | --- | --- | --- | --- |
| `--ui-border-default` | `border-default`, `ring-default`, `divide-default`, `bg-border` | Cards, menus, separators, table rows | `neutral-200` | `neutral-800` |
| `--ui-border-strong` | `border-strong`, `ring-strong` | Checkboxes, radios, the `outline` neutral variant | `neutral-300` | `neutral-700` |
| `--ui-overlay-border-default`, `--ui-overlay-border-strong` | The same utilities on a floating layer | Rings and separators in a menu | Unset, one step up from the page | Same |

### Per-color roles

Each color has twelve role variables, unset by default, so each role keeps its recipe: a mix of the color at a fixed opacity. Set one to change that role for one color in every component.

| Variable | Utility | Read by | Default |
| --- | --- | --- | --- |
| `--ui-<color>-bg-hover` | `bg-accent-hover` | A hovered `solid` | The color at 75% |
| `--ui-<color>-bg-tint` | `bg-accent-tint` | Callouts, highlighted menu items | The color at 5% |
| `--ui-<color>-bg-soft` | `bg-accent-soft` | The `soft` and `subtle` variants | The color at 10% |
| `--ui-<color>-bg-strong` | `bg-accent-strong` | A hovered `soft` or `subtle` | The color at 15% |
| `--ui-<color>-text-strong` | `text-<color>`, `text-accent` | Links in prose, colored text | `--ui-<color>-text-default` |
| `--ui-<color>-text-default` | `text-accent-default` | The `soft`, `subtle`, `outline` and `ghost` labels | The color |
| `--ui-<color>-text-muted` | `text-accent-muted` | The `link` Button, the Avatar fallback | The text at 75% |
| `--ui-<color>-text-faint` | `text-accent-faint` | Menu item icons, list markers | The text at 50% |
| `--ui-<color>-text-contrast` | `text-accent-contrast` | Text on the `solid` variant | `--ui-text-contrast` |
| `--ui-<color>-border-default` | `border-accent-default` | Callouts, colored separators | The color at 25% |
| `--ui-<color>-border-strong` | `ring-accent-strong` | The `outline` and `subtle` variants | The color at 50% |
| `--ui-<color>-outline-focus` | `outline-accent-focus` | The focus outline | The color at 25% |

`--ui-neutral-<role>` works the same, and defaults to the neutral token of the same name. `--ui-outline-focus` sets the focus outline of components without a `color` prop, `primary` at 25% by default.

### Layout and shape

| Variable | Read by | Default |
| --- | --- | --- |
| `--ui-radius` | The `rounded-xs` to `rounded-3xl` utilities, as multiples of it | `0.25rem` |
| `--ui-focus-width` | The width of every focus outline | `3px` |
| `--ui-disabled-opacity` | Disabled components and items | `75%` |
| `--ui-control-px`, `--ui-control-py`, `--ui-control-gap`, `--ui-control-icon-size` | Buttons, badges, fields, NavigationMenu links | Set per `size` by each component |
| `--ui-control-text-step` | Added to the text size of a field | `0px` |
| `--ui-control-size` | Cells of Calendar, indicators of Stepper, the spacing around Timeline indicators | Set per `size` |
| `--ui-control-thickness` | Tracks of Slider and Progress, Separator lines | Set per `size` |
| `--ui-container-width` | The maximum width of Container | `80rem` |
| `--ui-gutter` | The side padding of Container and of Card, Modal and Slideover parts | `--spacing(4)`, `--spacing(6)` from `sm` |
| `--ui-header-height` | Header, the height left to Main and Error, the offset of PageAside | `4rem` |

### Typography and charts

| Variable | Read by | Default |
| --- | --- | --- |
| `--font-heading` | `h1` to `h6`, Prose headings, component titles | Unset, the body font |
| `--ui-font-weight-heading` | Prose headings and component titles | Unset, each title's own weight |
| `--ui-font-weight-body` | The body text | Unset, `400` |
| `--ui-chart-1` to `--ui-chart-6` | The series of Chart, in order | `--ui-primary`, then `blue`, `violet`, `amber`, `rose` and `cyan` |

## Palette and aliases

Start with the colors. Declare each palette of your design system in `@theme`, every shade from `50` to `950`, and point the aliases at them with the `@nuxt/ui/colors` plugin. Map your semantic names onto the aliases by purpose, like `danger` onto `error`:

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

@theme {
  --color-acme-blue-50: #eef4ff;
  /* ...every shade... */
  --color-acme-blue-950: #0b1a3d;

  --color-acme-gray-50: #f8f9fb;
  /* ...every shade... */
  --color-acme-gray-950: #0c0e12;
}

@plugin "@nuxt/ui/colors" {
  primary: acme-blue 600 400;
  error: rose;
  neutral: acme-gray;
}
```

When your design system names the shade of a color in each mode, give both after the palette, light mode first. `neutral` colors the text, backgrounds and borders too, so a neutral palette that matches yours gets most of the surfaces right before the next step.

::note{to="/docs/getting-started/theme/design-system#change-colors-at-runtime"}
For a brand color without a scale, set `--ui-primary` itself in both modes. Shade utilities like `bg-primary-600` then don't follow it.
::

## Added colors

A color beyond the seven aliases gets its own name in the plugin, and every `color` prop takes it:

```css [app/assets/css/main.css]
@plugin "@nuxt/ui/colors" {
  primary: acme-blue 600 400;
  discovery: acme-purple;
}
```

The name can't be one a utility already has, like `accent`, `muted` or `teal`, and it can't be the name of its palette. When your design system calls a color `accent`, give it another name here and keep the mapping in a comment.

::tip{to="/docs/getting-started/theme/design-system#extend-colors"}
An added color has the same per-color roles as the aliases, like `--ui-discovery-text-contrast`.
::

## Surface and text roles

Then map the text, background and border tokens of your design system onto the variables of the [contract](#text), in both modes. Only set the ones that differ from the shades of your `neutral` palette:

```css [app/assets/css/main.css]
:root {
  --ui-text-muted: var(--ui-color-neutral-600);
  --ui-bg-soft: var(--ui-color-neutral-50);
  --ui-border-default: var(--ui-color-neutral-100);
}

.dark {
  --ui-bg-default: var(--ui-color-neutral-950);
  --ui-bg-overlay: var(--ui-color-neutral-900);
}
```

Read the values through the shade variables, `var(--ui-color-neutral-600)`, rather than the palette, `var(--color-acme-gray-600)`, so they follow the plugin when you change it.

A token that belongs to one color, like the text on a warning button or a darker link, goes in its [per-color role](#per-color-roles):

```css [app/assets/css/main.css]
:root {
  --ui-warning-text-contrast: var(--ui-color-neutral-900);
  --ui-primary-text-default: var(--ui-color-primary-700);
}

.dark {
  --ui-primary-text-default: initial;
}
```

The disabled state and the overlay follow the same way, through `--ui-disabled-opacity` and `--ui-bg-overlay`. The focus outline of a component follows its color, so a single focus color goes in `--ui-outline-focus` and in the `--ui-<color>-outline-focus` of each color, with `--ui-focus-width` for its width.

## Radius

Set `--ui-radius` to the radius of your design system's controls divided by `1.5`. Controls, menus and popovers use `rounded-md`, one and a half times the base, and cards, alerts, toasts and modals use `rounded-lg`, twice the base:

```css [app/assets/css/main.css]
:root {
  /* 6px controls, 8px cards */
  --ui-radius: 0.25rem;
}
```

When the scale of your design system isn't proportional, like 6px controls and 12px cards, set the steps that differ in `@theme`. `--ui-radius` still sets the others:

```css [app/assets/css/main.css]
@theme {
  --radius-md: 0.375rem;
  --radius-lg: 0.75rem;
}
```

::warning
The steps are the `rounded-*` utilities of Tailwind CSS, so they also change your own markup and other libraries.
::

## Control sizing

Each component sets its `--ui-control-*` variables in its `size` variants, so `:root` can't change them. Button and Input are `24px`, `28px`, `32px`, `36px` and `40px` high from `xs` to `xl`, the line height of their text plus twice `--ui-control-py`.

When your design system's default control matches another size, change the default size of every component first:

::framework-only
#nuxt
:::div
```ts [app/app.config.ts]
export default defineAppConfig({
  ui: {
    defaultVariants: {
      size: 'sm'
    }
  }
})
```
:::

#vue
:::div
```ts [src/main.ts]
app.use(ui, {
  ui: {
    defaultVariants: {
      size: 'sm'
    }
  }
})
```
:::
::

Then retune the sizes whose padding, gap or icon still differ: set their variables in the app config of each component that has it, rather than paddings, so icon-only buttons stay square and fields keep their icon spacing:

::framework-only
#nuxt
:::div
```ts [app/app.config.ts]
export default defineAppConfig({
  ui: {
    button: {
      variants: {
        size: {
          md: { base: '[--ui-control-px:--spacing(2)] [--ui-control-py:--spacing(1)] [--ui-control-icon-size:--spacing(4)]' }
        }
      }
    },
    input: {
      variants: {
        size: {
          md: { root: '[--ui-control-px:--spacing(2)] [--ui-control-py:--spacing(1)] [--ui-control-icon-size:--spacing(4)]' }
        }
      }
    }
  }
})
```
:::

#vue
:::div
```ts [src/main.ts]
app.use(ui, {
  ui: {
    button: {
      variants: {
        size: {
          md: { base: '[--ui-control-px:--spacing(2)] [--ui-control-py:--spacing(1)] [--ui-control-icon-size:--spacing(4)]' }
        }
      }
    },
    input: {
      variants: {
        size: {
          md: { root: '[--ui-control-px:--spacing(2)] [--ui-control-py:--spacing(1)] [--ui-control-icon-size:--spacing(4)]' }
        }
      }
    }
  }
})
```
:::
::

The key is the component, not its theme: Textarea, InputMenu, InputNumber, InputTags, InputDate, Select and SelectMenu each need their own entry next to Input. The [`get-component-theme`](/docs/getting-started/ai/mcp) tool of the MCP server lists the variables each component sets.

::tip
To make the whole interface denser, paddings and gaps included, change Tailwind CSS's spacing unit instead: `@theme { --spacing: 0.225rem; }`.
::

## Fonts

Set the font families in `@theme`, and the weights as CSS variables:

```css [app/assets/css/main.css]
@theme {
  --font-sans: 'Inter', system-ui, sans-serif;
  --font-heading: 'Inter Display', var(--font-sans);
  --font-mono: 'JetBrains Mono', monospace;
}

:root {
  --ui-font-weight-body: 400;
  --ui-font-weight-heading: 600;
}
```

A type scale goes in Tailwind CSS's `--text-*` variables, which components use through `text-xs` to `text-base`. See [Fonts](/docs/getting-started/theme/design-system#fonts) and [Font](/docs/getting-started/theme/css-variables#font).

## App config

Use the [app config](/docs/getting-started/theme/components#global-config) last, for the decisions that belong to one component rather than to a token: a pill Button, uppercase Badge labels, a heavier Tabs indicator, or a default `color` and `variant`:

::framework-only
#nuxt
:::div
```ts [app/app.config.ts]
export default defineAppConfig({
  ui: {
    button: {
      slots: {
        base: 'rounded-full'
      }
    },
    badge: {
      slots: {
        base: 'uppercase tracking-wide'
      },
      defaultVariants: {
        variant: 'subtle'
      }
    }
  }
})
```
:::

#vue
:::div
```ts [src/main.ts]
app.use(ui, {
  ui: {
    button: {
      slots: {
        base: 'rounded-full'
      }
    },
    badge: {
      slots: {
        base: 'uppercase tracking-wide'
      },
      defaultVariants: {
        variant: 'subtle'
      }
    }
  }
})
```
:::
::

Keep the classes semantic there too, `bg-soft` rather than `bg-gray-100`, so they follow the variables in both modes.

## Your own components

The components of your design system that Nuxt UI doesn't have can read the same tokens. Write their theme with the semantic utilities, give it a `color` variant with `colorVariant` so it takes every color, the ones you added included, and style the component with `useComponentTheme`:

```vue [app/components/AcmeTag.vue]
<script lang="ts">
import type { ComponentThemeConfig } from '@nuxt/ui'
import { colorVariant, defineTheme } from '@nuxt/ui/utils/theme'

const theme = defineTheme({
  slots: {
    root: 'inline-flex items-center gap-1 rounded-full px-2 py-0.5 text-xs font-medium',
    icon: 'size-3.5 shrink-0'
  },
  variants: {
    color: colorVariant({ root: '' }),
    variant: {
      soft: { root: 'bg-accent-soft text-accent-default' },
      outline: { root: 'ring ring-inset ring-accent-strong text-accent-default' }
    }
  },
  defaultVariants: {
    color: 'primary',
    variant: 'soft'
  }
})

type AcmeTag = ComponentThemeConfig<typeof theme, 'acmeTag'>

export interface AcmeTagProps {
  label: string
  icon?: string
  color?: AcmeTag['variants']['color']
  variant?: AcmeTag['variants']['variant']
  class?: any
  ui?: AcmeTag['slots']
}
</script>

<script setup lang="ts">
const _props = defineProps<AcmeTagProps>()

const { props, ui } = useComponentTheme('acmeTag', _props, theme)
</script>

<template>
  <span :class="ui.root()">
    <UIcon v-if="props.icon" :name="props.icon" :class="ui.icon()" />
    {{ props.label }}
  </span>
</template>
```

`colorVariant` puts the `[--ui-accent:…]` scope of each color on the slots you give it, next to their classes, so the `accent` utilities of the other variants read that color. A color you add takes `primary`'s classes with its own scope and joins the type of the `color` prop, so `<AcmeTag color="discovery" label="New" />` works once `discovery` is in the plugin, with no entry in the theme or the app config.

::note{to="/docs/getting-started/theme/components#custom-components"}
See Custom components to build on a Nuxt UI theme with `extendTheme` and to type the component's config.
::

## Check the result

The [ESLint config](/docs/getting-started/integrations/eslint/nuxt) reads your `@plugin "@nuxt/ui/colors"` block. Its `no-palette-colors` rule reports a raw palette class like `bg-acme-blue-600` or `text-gray-500` and suggests the alias or the token, so a class left behind by the migration shows up in the editor. Set it to `error` while you adopt your design system:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxt/eslint', '@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    eslint: {
      rules: {
        'no-palette-colors': 'error'
      }
    }
  }
})
```
