You theme Nuxt UI from your `main.css`. Point the color aliases at palettes, override the [tokens](/docs/getting-started/theme/css-variables) you need, and extend Tailwind's `@theme` like in any Tailwind project.

## Color system

Components take one of seven color aliases, named after what the color is for:

| Color | Default | Used for |
| --- | --- | --- |
| `primary`{color="primary"} | `sky` | Main actions, active navigation, links, brand elements |
| `secondary`{color="secondary"} | `violet` | Secondary actions and complementary elements |
| `success`{color="success"} | `emerald` | Success messages and completed states |
| `info`{color="info"} | `blue` | Information and help |
| `warning`{color="warning"} | `amber` | Warnings and pending states |
| `error`{color="error"} | `red` | Errors, validation and destructive actions |
| `neutral` | `gray` | Text, borders, backgrounds and disabled states |

Each alias points at a Tailwind palette and uses one shade of it per mode. `neutral` also colors the page: the text, background and border [tokens](/docs/getting-started/theme/css-variables) are shades of its palette.

The `color` prop picks the alias a component uses for its fills, text and borders. These are its [accent roles](/docs/getting-started/theme/css-variables#accent). Each alias is also a Tailwind color, so `text-primary`, `bg-error/10` or `border-success-300` work in your own markup.

::note
Try the :prose-icon{name="i-lucide-palette" class="text-primary"} theme menu in the header, or open the [theme editor](/theme) to customize everything at once.
::

### Configure colors

Point the aliases at other palettes with the `@nuxt/ui/colors` plugin in your `main.css`, after the imports. The aliases you leave out keep their default:

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

@plugin "@nuxt/ui/colors" {
  primary: blue;
  secondary: purple;
  neutral: zinc;
}
```

The shades of each palette are available as `--ui-color-primary-50` to `--ui-color-primary-950`. An alias uses `500` in light mode and `400` in dark mode, `neutral` uses `900` and `50`. To pick other shades, give both after the palette, light mode first:

```css [app/assets/css/main.css]
@plugin "@nuxt/ui/colors" {
  primary: neutral 900 50;
  secondary: indigo 600 400;
}
```

The first line makes primary monochrome with Tailwind's `neutral` palette, not the `neutral` alias. `black` and `white` work as shades too, and shades alone keep the palette, like `primary: black white`.

::note
An alias on a gray palette, or on the palette of `neutral`, styles its `soft`, `outline`, `subtle`, `ghost` and `link` variants like `color="neutral"`.
::

A palette changes everything built on it, so `neutral: zinc` changes the text, backgrounds and borders. Shades only change the alias, so `neutral: black white` changes a solid neutral Button but not the page. To change one surface, override its [token](/docs/getting-started/theme/css-variables).

A palette is any Tailwind palette, or one you declare in `@theme` with every shade from `50` to `950`:

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

@theme {
  --color-brand-50: #fef2f2;
  --color-brand-100: #fee2e2;
  --color-brand-200: #fecaca;
  --color-brand-300: #fca5a5;
  --color-brand-400: #f87171;
  --color-brand-500: #ef4444;
  --color-brand-600: #dc2626;
  --color-brand-700: #b91c1c;
  --color-brand-800: #991b1b;
  --color-brand-900: #7f1d1d;
  --color-brand-950: #450a0a;
}

@plugin "@nuxt/ui/colors" {
  primary: brand;
}
```

Overriding a Tailwind palette in `@theme`, like `--color-sky-500`, also changes the aliases that use it. With a [Tailwind prefix](/docs/getting-started/installation/nuxt#tailwindprefix), list those aliases in the plugin too.

::tip
To reset the palettes with `--color-*: initial`, put that `@theme` block between `@import "tailwindcss"` and `@import "@nuxt/ui"`. After the Nuxt UI import, it also removes utilities like `bg-primary`.
::

The plugin reads the palettes from its own stylesheet. In one that doesn't import Tailwind CSS, like in a [Nuxt layer](https://nuxt.com/docs/getting-started/layers), import the theme for reference first:

```css [layers/brand/app/assets/css/main.css]
@import "tailwindcss/theme" theme(reference);

@plugin "@nuxt/ui/colors" {
  primary: indigo;
}
```

### Change colors at runtime

The plugin sets the colors at build time. To change them at runtime, from a color picker or per tenant, render a `<style>` that sets the shades of an alias on `:root`:

::code-group

```ts [app/utils/palettes.ts]
// From https://tailwindcss.com/docs/colors
export const palettes: Record<string, Record<number, string>> = {
  indigo: {
    50: 'oklch(96.2% 0.018 272.314)',
    100: 'oklch(93% 0.034 272.788)',
    200: 'oklch(87% 0.065 274.039)',
    300: 'oklch(78.5% 0.115 274.713)',
    400: 'oklch(67.3% 0.182 276.935)',
    500: 'oklch(58.5% 0.233 277.117)',
    600: 'oklch(51.1% 0.262 276.966)',
    700: 'oklch(45.7% 0.24 277.023)',
    800: 'oklch(39.8% 0.195 277.366)',
    900: 'oklch(35.9% 0.144 278.697)',
    950: 'oklch(25.7% 0.09 281.288)'
  }
  // ...the other palettes your picker offers
}
```

```vue [app/app.vue]
<script setup lang="ts">
const primary = useState('primary', () => 'indigo')

useHead(() => ({
  style: [{
    innerHTML: `:root { ${Object.entries(palettes[primary.value] ?? {}).map(([shade, value]) => `--ui-color-primary-${shade}: ${value};`).join(' ')} }`,
    // After the stylesheets, so it also wins over your own unlayered `:root` rules
    tagPriority: 'low'
  }]
}))
</script>

<template>
  <UApp>
    <USelect v-model="primary" :items="Object.keys(palettes)" />
  </UApp>
</template>
```

::

Keep the palettes you offer in your own file. Importing `tailwindcss/colors` would ship all of them to the browser.

::framework-only
#vue
:::note
Import `useHead` from `@unhead/vue` and keep the state in a `ref`.
:::
::

The alias keeps the shades the plugin picked, now taken from the new palette. [`--ui-radius`](/docs/getting-started/theme/css-variables#radius) works the same way.

To give a subtree its own colors, set the shades and the alias on it. The alias resolves on `:root`, so with the shades alone only utilities like `bg-primary-500` change:

```css [app/assets/css/main.css]
[data-theme='rose'] {
  --ui-color-primary-500: var(--color-rose-500);
  --ui-color-primary-400: var(--color-rose-400);
  --ui-primary: var(--ui-color-primary-500);
}

.dark [data-theme='rose'] {
  --ui-primary: var(--ui-color-primary-400);
}
```

For a single brand color, set the alias itself, on `.light` and `.dark` too: `:root, .light, .dark { --ui-primary: #5647ff; }`. Components follow it, but shade utilities like `bg-primary-600` don't. `neutral` needs a full palette since the surfaces use its shades.

::warning
A value that comes from a database or a URL lands in a `<style>` tag. Check that it's a color first, like `/^#(?:[0-9a-f]{3,4}){1,2}$/i` for a hex color, or it can close the rule or the tag.
::

### Extend colors

The `color` prop accepts the seven aliases above. To use another color, declare it in your `main.css` and bridge it to Tailwind so it gets utilities like `bg-tertiary`:

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

@theme inline {
  --color-tertiary: var(--ui-tertiary);
}

:root {
  --ui-tertiary: var(--color-indigo-500);
}

.dark {
  --ui-tertiary: var(--color-indigo-400);
}
```

With a [Tailwind prefix](/docs/getting-started/installation/nuxt#tailwindprefix), use the prefixed variable, like `--tw-color-indigo-500`.

Point a component's `--ui-accent` at it through `class` to use it:

```vue
<template>
  <UButton class="[--ui-accent:var(--ui-tertiary)]" label="Special action" />
  <UInput highlight class="[--ui-accent:var(--ui-tertiary)]" />
</template>
```

A custom color has no [role variables](/docs/getting-started/theme/css-variables#accent). Set a role next to it when you need one, like `[--ui-accent-text-contrast:var(--ui-color-neutral-900)]`.

To use it through the `color` prop, add it to the `color` variant of each component, on its root slot. That's `base` for Button and `root` for Input:

::framework-only
#nuxt
:::div

```ts [app/app.config.ts]
export default defineAppConfig({
  ui: {
    button: {
      variants: {
        color: {
          tertiary: { base: '[--ui-accent:var(--ui-tertiary)]' }
        }
      }
    },
    input: {
      variants: {
        color: {
          tertiary: { root: '[--ui-accent:var(--ui-tertiary)]' }
        }
      }
    }
  }
})
```

:::

#vue
:::div

```ts [vite.config.ts]
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      ui: {
        button: {
          variants: {
            color: {
              tertiary: { base: '[--ui-accent:var(--ui-tertiary)]' }
            }
          }
        },
        input: {
          variants: {
            color: {
              tertiary: { root: '[--ui-accent:var(--ui-tertiary)]' }
            }
          }
        }
      }
    })
  ]
})
```

:::
::

`<UButton color="tertiary" />` then works like the built-in colors.

::framework-only
#nuxt
:::note
It type-checks too: Nuxt UI adds the values from your `app.config.ts` to the component's prop types.
:::

#vue
:::note
The `vite.config.ts` options aren't part of the prop types, so `color="tertiary"` works at runtime but fails type checking.
:::
::

## Fonts, breakpoints and motion

Fonts, breakpoints and easings are regular [Tailwind theme variables](https://tailwindcss.com/docs/theme): set `--font-*`, `--breakpoint-*` or `--ease-*` in `@theme` and Nuxt UI follows.

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

@theme {
  --font-sans: 'Public Sans', system-ui, sans-serif;
  --breakpoint-3xl: 1920px;
  --ease-out: cubic-bezier(0.16, 1, 0.3, 1);
}
```

::framework-only
#nuxt
:::note{to="/docs/getting-started/integrations/fonts"}
Fonts defined here are automatically loaded and optimized by the `@nuxt/fonts` module.
:::
::

Enter and exit animations use `--ease-out`, the `swing` and `elastic` loading animations use `--ease-in-out`. With `prefers-reduced-motion`, overlays fade instead of scaling or sliding, and movement transitions are off.

::tip
Tailwind CSS v4 changed its [Preflight](https://tailwindcss.com/docs/upgrade-guide#buttons-use-the-default-cursor) so that buttons use `cursor: default` instead of `cursor: pointer` to match browser defaults. If you'd like to restore the pointer cursor globally, add these base styles to your CSS:

```css [app/assets/css/main.css]
@layer base {
  button:not(:disabled),
  [role="button"]:not(:disabled) {
    cursor: pointer;
  }
}
```
::
