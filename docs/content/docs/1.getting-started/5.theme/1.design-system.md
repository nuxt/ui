## Tailwind CSS

Tailwind CSS uses a CSS-first configuration, letting you define your design tokens with the [`@theme`](https://tailwindcss.com/docs/functions-and-directives#theme-directive) directive directly in your CSS. This makes your theme portable, maintainable and easy to customize.

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

@theme {
  /* Your custom design tokens go here */
}
```

::note{to="https://tailwindcss.com/docs/theme" target="_blank"}
Check the Tailwind CSS documentation for all available theme variable customization options.
::

::tip
Tailwind CSS v4 changed its [Preflight](https://tailwindcss.com/docs/upgrade-guide#buttons-use-the-default-cursor) so that buttons use `cursor: default` instead of `cursor: pointer` to match browser defaults. If you'd like to restore the pointer cursor globally, add these base styles to your CSS:

```css [app/assets/css/main.css]
@layer base {
  button:not(:disabled),
  [role="button"]:not(:disabled) {
    cursor: pointer;
  }
}
```

::

### Fonts

Use the `--font-*` theme variables to [customize the font family utilities](https://tailwindcss.com/docs/font-family#customizing-your-theme) in your project.

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

@theme {
  --font-sans: 'Public Sans', system-ui, sans-serif;
  --font-mono: 'JetBrains Mono', monospace;
}
```

::framework-only
#nuxt
:::note{to="/docs/getting-started/integrations/fonts"}
Fonts defined here are automatically loaded and optimized by the `@nuxt/fonts` module.
:::
::

### Colors

Use the `--color-*` theme variables to [customize your colors](https://tailwindcss.com/docs/colors#customizing-your-colors) or [override default colors](https://tailwindcss.com/docs/colors#overriding-default-colors).

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

@theme static {
  /* Override default green color */
  --color-green-50: #EFFDF5;
  --color-green-100: #D9FBE8;
  --color-green-200: #B3F5D1;
  --color-green-300: #75EDAE;
  --color-green-400: #00DC82;
  --color-green-500: #00C16A;
  --color-green-600: #00A155;
  --color-green-700: #007F45;
  --color-green-800: #016538;
  --color-green-900: #0A5331;
  --color-green-950: #052E16;

  /* Define new custom color */
  --color-brand-50: #fef2f2;
  --color-brand-100: #fee2e2;
  --color-brand-200: #fecaca;
  --color-brand-300: #fca5a5;
  --color-brand-400: #f87171;
  --color-brand-500: #ef4444;
  --color-brand-600: #dc2626;
  --color-brand-700: #b91c1c;
  --color-brand-800: #991b1b;
  --color-brand-900: #7f1d1d;
  --color-brand-950: #450a0a;
}
```

::warning
When adding custom colors, make sure to define all shades from `50` to `950` for each color.
::

::tip
To start from an empty palette with `--color-*: initial`, put that `@theme` block between `@import "tailwindcss"` and `@import "@nuxt/ui"`. After the Nuxt UI import, it also removes the color tokens behind utilities like `bg-primary` and `bg-accent`.
::

### Breakpoints

Use the `--breakpoint-*` theme variables to [customize your breakpoints](https://tailwindcss.com/docs/responsive-design#customizing-your-theme).

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

@theme {
  --breakpoint-3xl: 1920px;
  --breakpoint-4xl: 2560px;
  --breakpoint-5xl: 3840px;
}
```

### Motion

Use the `--ease-*` theme variables to [customize the easing](https://tailwindcss.com/docs/transition-timing-function#customizing-your-theme) of the animations and movement transitions in your project.

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

@theme {
  --ease-out: cubic-bezier(0.16, 1, 0.3, 1);
}
```

Enter and exit animations run on `--ease-out`, indeterminate loading animations on `--ease-in-out`, so overriding these two retimes the library.

::note
When `prefers-reduced-motion` is set, overlays fade in place instead of scaling or sliding and movement transitions are disabled.
::

## Color System

Nuxt UI's color system is designed around **semantic naming** rather than specific color values. This approach makes your UI more maintainable and makes theme switching easy.

### Semantic colors

Nuxt UI provides semantic color aliases that describe the **purpose** of the color. Each alias is defined based on a color from your `@theme` configuration, which can be any color you define in addition to the [default Tailwind CSS palette](https://tailwindcss.com/docs/colors).

| Color | Default | Description |
| --- | --- | --- |
| `primary`{color="primary"} | `green` | Main CTAs, active navigation, brand elements, important links |
| `secondary`{color="secondary"} | `blue` | Secondary buttons, alternative actions, complementary UI elements |
| `success`{color="success"} | `green` | Success messages, completed states, positive confirmations |
| `info`{color="info"} | `blue` | Info alerts, tooltips, help text, neutral notifications |
| `warning`{color="warning"} | `yellow` | Warning messages, pending states, attention-needed items |
| `error`{color="error"} | `red` | Error messages, validation errors, destructive actions |
| `neutral` | `slate` | Text, borders, backgrounds, disabled states |

These semantic colors are available in the `color` prop of Nuxt UI components:

::component-code{slug="button"}
---
props:
  color: primary
slots:
  default: Save Changes
---
::

::note
Try the :prose-icon{name="i-lucide-palette" class="text-primary"} theme menu in the header to instantly see how different color schemes affect the entire UI, or open the [theme editor](/theme) to customize everything at once!
::

### Configure colors :badge{label="Soon" class="align-text-top"}

Point the aliases at other palettes with the `@nuxt/ui/colors` plugin in your `main.css`, after the imports. The aliases you leave out keep their default:

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

@plugin "@nuxt/ui/colors" {
  primary: blue;
  secondary: purple;
  neutral: zinc;
}
```

Each alias takes the palette's shades from `50` to `950` when Tailwind compiles your CSS, as `--ui-color-primary-50` to `--ui-color-primary-950`. The alias itself uses shade `500` in light mode and `400` in dark mode. Pick others after the palette, for light then dark mode, or give one shade for both:

```css [app/assets/css/main.css]
@plugin "@nuxt/ui/colors" {
  primary: neutral 900 200;
  secondary: indigo 600;
}
```

`neutral` uses shade `900` in light mode and `50` in dark mode, the ends of its palette, and takes others the same way. `black` and `white` work as shades too, and shades alone keep the alias's palette, like `primary: black white`. An alias on a gray palette, like `primary: neutral 900 50`, or on the palette `neutral` uses, is monochrome: its `soft`, `outline`, `subtle` and `link` variants take the surface colors of `color="neutral"` instead of tints of the gray, like shadcn/ui's buttons. A palette you override in `@theme`, like `green` above, carries over to the aliases that use it. With a [Tailwind prefix](/docs/getting-started/installation/nuxt#tailwindprefix), Tailwind renames the palettes, so the default aliases keep Tailwind's values: list the aliases in the plugin for an override to carry over.

::caution
You can only use palettes that exist in your theme. Either:
- Use [Tailwind's default colors](https://tailwindcss.com/docs/colors) (like `blue`, `green`, `zinc`)
- Define custom colors first using the `@theme` directive (like `brand` in our example above)
::

The plugin reads the palettes from the Tailwind CSS theme of the stylesheet it sits in. In a stylesheet that doesn't import Tailwind CSS, like one a [Nuxt layer](https://nuxt.com/docs/getting-started/layers) adds to set its colors, import the theme for reference first:

```css [layers/brand/app/assets/css/main.css]
@import "tailwindcss/theme" theme(reference);

@plugin "@nuxt/ui/colors" {
  primary: indigo;
}
```

### Change colors at runtime :badge{label="Soon" class="align-text-top"}

The plugin sets the colors when Tailwind compiles your CSS. To change them at runtime, from a color picker or per tenant, render a `<style>` that sets the shades of an alias. Tailwind only outputs the palettes your CSS uses, so give it the values themselves. `tailwindcss/colors` can't be tree-shaken and would ship every palette to the browser, so keep the ones your picker offers in a file of your own. With Vue, import `useHead` from `@unhead/vue` and keep the state in a `ref`:

::code-group

```ts [app/utils/palettes.ts]
// From https://tailwindcss.com/docs/colors
export const palettes: Record<string, Record<number, string>> = {
  indigo: {
    50: 'oklch(96.2% 0.018 272.314)',
    100: 'oklch(93% 0.034 272.788)',
    200: 'oklch(87% 0.065 274.039)',
    300: 'oklch(78.5% 0.115 274.713)',
    400: 'oklch(67.3% 0.182 276.935)',
    500: 'oklch(58.5% 0.233 277.117)',
    600: 'oklch(51.1% 0.262 276.966)',
    700: 'oklch(45.7% 0.24 277.023)',
    800: 'oklch(39.8% 0.195 277.366)',
    900: 'oklch(35.9% 0.144 278.697)',
    950: 'oklch(25.7% 0.09 281.288)'
  },
  emerald: {
    50: 'oklch(97.9% 0.021 166.113)',
    100: 'oklch(95% 0.052 163.051)',
    200: 'oklch(90.5% 0.093 164.15)',
    300: 'oklch(84.5% 0.143 164.978)',
    400: 'oklch(76.5% 0.177 163.223)',
    500: 'oklch(69.6% 0.17 162.48)',
    600: 'oklch(59.6% 0.145 163.225)',
    700: 'oklch(50.8% 0.118 165.612)',
    800: 'oklch(43.2% 0.095 166.913)',
    900: 'oklch(37.8% 0.077 168.94)',
    950: 'oklch(26.2% 0.051 172.552)'
  }
}
```

```vue [app/app.vue]
<script setup lang="ts">
const primary = useState('primary', () => 'indigo')

useHead(() => ({
  style: [{
    innerHTML: `:root { ${Object.entries(palettes[primary.value] ?? {}).map(([shade, value]) => `--ui-color-primary-${shade}: ${value};`).join(' ')} }`,
    // After the stylesheets, so it also wins over your own unlayered `:root` rules
    tagPriority: 'low'
  }]
}))
</script>

<template>
  <UApp>
    <USelect v-model="primary" :items="Object.keys(palettes)" />
  </UApp>
</template>
```

::

A palette goes on `:root`, where the plugin sets it, so dark mode keeps its lighter shade and a subtree that sets its own shades keeps them. `--ui-radius` changes the same way.

A single color, like a brand color stored per tenant, sets the alias itself. Set it on `.light` and `.dark` too, where your CSS points each alias at a shade of the mode: `:root, .light, .dark { --ui-primary: #5647ff; }`. It recolors the components but not the shade utilities like `bg-primary-600`. `neutral` needs a palette, since the surfaces use its shades.

::warning
A value that comes from a database or a URL lands in a `<style>` tag. Check that it's a color first, like `/^#(?:[0-9a-f]{3,4}){1,2}$/i` for a hex color, or it can close the rule or the tag.
::

### Extend colors

The `color` prop accepts the seven aliases above. To use another color, declare it in your `main.css` and bridge it to Tailwind so it gets utilities like `bg-tertiary`:

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

@theme inline {
  --color-tertiary: var(--ui-tertiary);
}

:root {
  --ui-tertiary: var(--color-indigo-500);
}

.dark {
  --ui-tertiary: var(--color-indigo-400);
}
```

Components read their color from the `--ui-accent` variable, so point it at your color through `class` to use it on one of them:

```vue
<template>
  <UButton class="[--ui-accent:var(--ui-tertiary)]" label="Special action" />
  <UInput highlight class="[--ui-accent:var(--ui-tertiary)]" />
</template>
```

To use it through the `color` prop instead, add it to the `color` variant of the components that need it, setting `--ui-accent` on their root slot (`base` for Button, `root` for Input):

::framework-only
#nuxt
:::div

```ts [app.config.ts]
export default defineAppConfig({
  ui: {
    button: {
      variants: {
        color: {
          tertiary: { base: '[--ui-accent:var(--ui-tertiary)]' }
        }
      }
    },
    input: {
      variants: {
        color: {
          tertiary: { root: '[--ui-accent:var(--ui-tertiary)]' }
        }
      }
    }
  }
})
```

:::

#vue
:::div

```ts [vite.config.ts]
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      ui: {
        button: {
          variants: {
            color: {
              tertiary: { base: '[--ui-accent:var(--ui-tertiary)]' }
            }
          }
        },
        input: {
          variants: {
            color: {
              tertiary: { root: '[--ui-accent:var(--ui-tertiary)]' }
            }
          }
        }
      }
    })
  ]
})
```

:::
::

`<UButton color="tertiary" />` then works like the built-in colors.

::framework-only
#nuxt
:::note
It type-checks too: Nuxt UI adds the values from your `app.config.ts` to the component's prop types.
:::

#vue
:::note
The `vite.config.ts` options aren't part of the prop types, so `color="tertiary"` works at runtime but fails type checking.
:::
::
