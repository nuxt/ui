Nuxt UI is themed with CSS variables and Tailwind CSS. You configure it in your `main.css`, after the imports: point the color aliases at palettes, override the tokens you want to change, and extend Tailwind's `@theme` like in any Tailwind project.

## Color system

Components don't take a color value. They take one of seven aliases, named after what the color is for, and each alias points at a Tailwind palette:

| Color | Default | Used for |
| --- | --- | --- |
| `primary`{color="primary"} | `green` | Main CTAs, active navigation, brand elements, important links |
| `secondary`{color="secondary"} | `blue` | Secondary buttons, alternative actions, complementary UI elements |
| `success`{color="success"} | `green` | Success messages, completed states, positive confirmations |
| `info`{color="info"} | `blue` | Info alerts, tooltips, help text, neutral notifications |
| `warning`{color="warning"} | `yellow` | Warning messages, pending states, attention-needed items |
| `error`{color="error"} | `red` | Error messages, validation errors, destructive actions |
| `neutral` | `slate` | Text, borders, backgrounds, disabled states |

The `color` prop of a component picks one of them. It sets a `--ui-accent` variable on the component, and the component's classes read that variable and its [accent roles](#accent), like the tinted background of a soft variant or the text on a solid one.

`neutral` also drives the surfaces: the text, background and border [tokens](#tokens) are shades of its palette. Each alias is a Tailwind color too, so `text-primary`, `bg-error/10` or `border-success-300` work in your own markup.

::note
Try the :prose-icon{name="i-lucide-palette" class="text-primary"} theme menu in the header to see how different colors affect the entire UI, or open the [theme editor](/theme) to customize everything at once.
::

### Configure colors :badge{label="Soon" class="align-text-top"}

Point the aliases at other palettes with the `@nuxt/ui/colors` plugin in your `main.css`, after the imports. The aliases you leave out keep their default:

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

@plugin "@nuxt/ui/colors" {
  primary: blue;
  secondary: purple;
  neutral: zinc;
}
```

Each alias takes the palette's shades from `50` to `950` when Tailwind compiles your CSS, as `--ui-color-primary-50` to `--ui-color-primary-950`. The alias itself uses shade `500` in light mode and `400` in dark mode. Pick others after the palette, for light then dark mode, or give one shade for both:

```css [app/assets/css/main.css]
@plugin "@nuxt/ui/colors" {
  primary: neutral black white;
  secondary: indigo 600;
}
```

`black` and `white` work as shades too, so the first line gives a black primary in light mode and a white one in dark mode, with Tailwind's `neutral` palette behind `primary-*` utilities. Shades alone keep the alias's palette, like `primary: black white`. `neutral` uses shades `900` and `50` by default, the ends of its palette, and takes others the same way.

Palettes and shades set different layers, and each layer is built from the one above:

| Layer | Variables | Built from | Set with |
| --- | --- | --- | --- |
| Palettes | `--ui-color-primary-50` to `950`… | A Tailwind palette | A palette in the plugin, `primary: indigo` |
| Aliases | `--ui-primary`, `--ui-neutral`… | One shade of the alias's palette per mode | Shades in the plugin, `neutral: black white` |
| [Tokens](#tokens) | `--ui-bg`, `--ui-text`, `--ui-border`… | Shades of the `neutral` palette | An override in your CSS |
| [Accent roles](#accent) | `--ui-accent-soft`, `--ui-accent-border`… | The alias the `color` prop picks | An override per color, like `--ui-primary-soft` |

A palette moves everything built from it, so `neutral: zinc` changes the text, backgrounds and borders. Shades only move the alias: `neutral: black white` changes a solid neutral Button and `bg-neutral`, and the page keeps its background. To change a surface on its own, override its [token](#tokens).

A palette is any Tailwind palette, or one you declare in `@theme` with every shade from `50` to `950`:

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

@theme {
  --color-brand-50: #fef2f2;
  --color-brand-100: #fee2e2;
  --color-brand-200: #fecaca;
  --color-brand-300: #fca5a5;
  --color-brand-400: #f87171;
  --color-brand-500: #ef4444;
  --color-brand-600: #dc2626;
  --color-brand-700: #b91c1c;
  --color-brand-800: #991b1b;
  --color-brand-900: #7f1d1d;
  --color-brand-950: #450a0a;
}

@plugin "@nuxt/ui/colors" {
  primary: brand;
}
```

A Tailwind palette you override in `@theme`, like `--color-green-500`, carries over to the aliases that use it. With a [Tailwind prefix](/docs/getting-started/installation/nuxt#tailwindprefix), Tailwind renames the palettes, so the default aliases keep Tailwind's values: list the aliases in the plugin for an override to carry over.

::tip
To start from an empty palette with `--color-*: initial`, put that `@theme` block between `@import "tailwindcss"` and `@import "@nuxt/ui"`. After the Nuxt UI import, it also removes the color tokens behind utilities like `bg-primary` and `bg-accent`.
::

The plugin reads the palettes from the Tailwind CSS theme of the stylesheet it sits in. In a stylesheet that doesn't import Tailwind CSS, like one a [Nuxt layer](https://nuxt.com/docs/getting-started/layers) adds to set its colors, import the theme for reference first:

```css [layers/brand/app/assets/css/main.css]
@import "tailwindcss/theme" theme(reference);

@plugin "@nuxt/ui/colors" {
  primary: indigo;
}
```

### Change colors at runtime :badge{label="Soon" class="align-text-top"}

The plugin sets the colors when Tailwind compiles your CSS. To change them at runtime, from a color picker or per tenant, render a `<style>` that sets the shades of an alias on `:root`. Tailwind only outputs the palettes your CSS uses, so give it the values themselves. Keep the palettes your picker offers in a file of your own: `tailwindcss/colors` can't be tree-shaken and would ship every palette to the browser. With Vue, import `useHead` from `@unhead/vue` and keep the state in a `ref`:

::code-group

```ts [app/utils/palettes.ts]
// From https://tailwindcss.com/docs/colors
export const palettes: Record<string, Record<number, string>> = {
  indigo: {
    50: 'oklch(96.2% 0.018 272.314)',
    100: 'oklch(93% 0.034 272.788)',
    200: 'oklch(87% 0.065 274.039)',
    300: 'oklch(78.5% 0.115 274.713)',
    400: 'oklch(67.3% 0.182 276.935)',
    500: 'oklch(58.5% 0.233 277.117)',
    600: 'oklch(51.1% 0.262 276.966)',
    700: 'oklch(45.7% 0.24 277.023)',
    800: 'oklch(39.8% 0.195 277.366)',
    900: 'oklch(35.9% 0.144 278.697)',
    950: 'oklch(25.7% 0.09 281.288)'
  }
  // ...the other palettes your picker offers
}
```

```vue [app/app.vue]
<script setup lang="ts">
const primary = useState('primary', () => 'indigo')

useHead(() => ({
  style: [{
    innerHTML: `:root { ${Object.entries(palettes[primary.value] ?? {}).map(([shade, value]) => `--ui-color-primary-${shade}: ${value};`).join(' ')} }`,
    // After the stylesheets, so it also wins over your own unlayered `:root` rules
    tagPriority: 'low'
  }]
}))
</script>

<template>
  <UApp>
    <USelect v-model="primary" :items="Object.keys(palettes)" />
  </UApp>
</template>
```

::

The style sets the palette on `:root`, like the plugin, so dark mode still uses the lighter shade. `--ui-radius` changes the same way.

To give a subtree its own colors, set its shades and its alias on it. The alias resolves on `:root`, so with the shades alone only `bg-primary-500` and the other shade utilities follow, not `bg-primary` or the components:

```css [app/assets/css/main.css]
[data-theme='rose'] {
  --ui-color-primary-500: var(--color-rose-500);
  --ui-color-primary-400: var(--color-rose-400);
  --ui-primary: var(--ui-color-primary-500);
}

.dark [data-theme='rose'] {
  --ui-primary: var(--ui-color-primary-400);
}
```

A single color, like a brand color stored per tenant, sets the alias itself. Set it on `.light` and `.dark` too, where your CSS points each alias at a shade of the mode: `:root, .light, .dark { --ui-primary: #5647ff; }`. It recolors the components but not the shade utilities like `bg-primary-600`. `neutral` needs a palette, since the surfaces use its shades.

::warning
A value that comes from a database or a URL lands in a `<style>` tag. Check that it's a color first, like `/^#(?:[0-9a-f]{3,4}){1,2}$/i` for a hex color, or it can close the rule or the tag.
::

### Extend colors

The `color` prop accepts the seven aliases above. To use another color, declare it in your `main.css` and bridge it to Tailwind so it gets utilities like `bg-tertiary`:

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

@theme inline {
  --color-tertiary: var(--ui-tertiary);
}

:root {
  --ui-tertiary: var(--color-indigo-500);
}

.dark {
  --ui-tertiary: var(--color-indigo-400);
}
```

With a [Tailwind prefix](/docs/getting-started/installation/nuxt#tailwindprefix), Tailwind's variables carry it too, like `--tw-color-indigo-500`.

Point a component's `--ui-accent` at it through `class` to use it:

```vue
<template>
  <UButton class="[--ui-accent:var(--ui-tertiary)]" label="Special action" />
  <UInput highlight class="[--ui-accent:var(--ui-tertiary)]" />
</template>
```

To use it through the `color` prop instead, add it to the `color` variant of the components that need it, setting `--ui-accent` on their root slot (`base` for Button, `root` for Input):

::framework-only
#nuxt
:::div

```ts [app.config.ts]
export default defineAppConfig({
  ui: {
    button: {
      variants: {
        color: {
          tertiary: { base: '[--ui-accent:var(--ui-tertiary)]' }
        }
      }
    },
    input: {
      variants: {
        color: {
          tertiary: { root: '[--ui-accent:var(--ui-tertiary)]' }
        }
      }
    }
  }
})
```

:::

#vue
:::div

```ts [vite.config.ts]
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      ui: {
        button: {
          variants: {
            color: {
              tertiary: { base: '[--ui-accent:var(--ui-tertiary)]' }
            }
          }
        },
        input: {
          variants: {
            color: {
              tertiary: { root: '[--ui-accent:var(--ui-tertiary)]' }
            }
          }
        }
      }
    })
  ]
})
```

:::
::

`<UButton color="tertiary" />` then works like the built-in colors.

::framework-only
#nuxt
:::note
It type-checks too: Nuxt UI adds the values from your `app.config.ts` to the component's prop types.
:::

#vue
:::note
The `vite.config.ts` options aren't part of the prop types, so `color="tertiary"` works at runtime but fails type checking.
:::
::

## Tokens

Every token is a CSS variable behind a Tailwind utility. `neutral-400` below stands for `var(--ui-color-neutral-400)`, so the surfaces follow the palette of `neutral`.

| Token | Light | Dark | Used for |
| --- | --- | --- | --- |
| `--ui-primary`, `--ui-secondary`, `--ui-success`, `--ui-info`, `--ui-warning`, `--ui-error` | Shade `500` | Shade `400` | `text-primary`, `bg-error`… |
| `--ui-neutral` | Shade `900` | Shade `50` | `text-neutral`, `bg-neutral`… |
| `--ui-text-dimmed` | `neutral-400` | `neutral-500` | `text-dimmed`, placeholders |
| `--ui-text-muted` | `neutral-500` | `neutral-400` | `text-muted`, descriptions |
| `--ui-text-toned` | `neutral-600` | `neutral-300` | `text-toned` |
| `--ui-text` | `neutral-700` | `neutral-200` | `text-default`, body text |
| `--ui-text-highlighted` | `neutral-900` | `white` | `text-highlighted`, titles |
| `--ui-text-inverted` | `white` | `neutral-900` | `text-inverted`, text on an inverted background |
| `--ui-bg` | `white` | `neutral-900` | `bg-default`, the page |
| `--ui-bg-muted` | `neutral-50` | `neutral-800` | `bg-muted` |
| `--ui-bg-elevated` | `neutral-100` | `neutral-800` | `bg-elevated`, raised surfaces |
| `--ui-bg-accented` | `neutral-200` | `neutral-700` | `bg-accented` |
| `--ui-bg-inverted` | `neutral-900` | `white` | `bg-inverted`, an inverted surface |
| `--ui-border` | `neutral-200` | `neutral-800` | `border-default` |
| `--ui-border-muted` | `neutral-200` | `neutral-700` | `border-muted` |
| `--ui-border-accented` | `neutral-300` | `neutral-700` | `border-accented` |
| `--ui-border-inverted` | `neutral-900` | `white` | `border-inverted` |
| `--ui-accent-foreground` | `--ui-text-inverted` | Same | `text-accent-foreground`, text on a solid accent background |
| `--ui-accent-hover` | `--ui-accent` at 75% | Same | `bg-accent-hover`, the hover of a solid background |
| `--ui-accent-soft` | `--ui-accent` at 10% | Same | `bg-accent-soft`, a tinted background |
| `--ui-accent-soft-foreground` | `--ui-accent` | Same | `text-accent-soft-foreground`, text on a tinted background |
| `--ui-accent-border` | `--ui-accent` at 50% | Same | `ring-accent-border`, a colored border |
| `--ui-accent-border-soft` | `--ui-accent` at 25% | Same | `ring-accent-border-soft`, a lighter colored border |
| `--ui-accent-focus` | `--ui-accent` at 25% | Same | `outline-accent-focus`, the focus outline |
| `--ui-radius` | `0.25rem` | Same | The base of the [`rounded-*` scale](#radius) |
| `--ui-container` | `80rem` | Same | The max width of [Container](#container) |
| `--ui-header-height` | `4rem` | Same | The height of [Header](#header) |

The border tokens also work with `ring-*` and `divide-*`, and every accent role works with any color utility, like `text-accent` or `border-accent-border`.

Override a token in your `main.css`. A value on `:root` applies in both modes, and one on `.dark` takes over in dark mode:

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

:root {
  --ui-bg: var(--ui-color-neutral-50);
}

.dark {
  --ui-bg: var(--ui-color-neutral-950);
}
```

To change all the surfaces at once, [give `neutral` another palette](#configure-colors) instead.

### Accent

The `color` prop puts a class like `[--ui-accent:var(--ui-primary)]` on the component. That class also points each accent role at a variable of the color, `--ui-primary-soft`, `--ui-primary-foreground` and so on. They are unset by default, so the roles take the values in the table. Set one to change a role of one color, and every component follows. For example, dark text on a yellow `warning`:

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

:root {
  --ui-warning-foreground: var(--ui-color-neutral-900);
}
```

`neutral` points its roles at the surface tokens instead (`bg-elevated`, `text-default`, `ring-accented`…), which is how a neutral component keeps its look. `--ui-neutral-soft` and the other `--ui-neutral-<role>` variables override them the same way. `color="neutral"` uses the same classes as every other color, except in Callout, inline Code, Calendar and ChatMessage. Components also read a few roles of their own that aren't listed here, which can change between versions.

The accent utilities work in your own markup too. Set `--ui-accent` through a class to pick the color:

```vue
<template>
  <div class="[--ui-accent:var(--ui-error)] bg-accent-soft text-accent-soft-foreground">
    Something went wrong
  </div>
</template>
```

The same class recolors a component outside its `color` prop, like `<UButton class="[--ui-accent:var(--color-indigo-500)]" />`. A few parts set their own and take it through `ui` instead: items with their own color in DropdownMenu, ContextMenu and ProgressGroup, the links of a NavigationMenu, the loading bar of a Table (`loading-color`), the indicator of a Timeline and the dot of a Chip. Components nested inside keep their own color too, like the buttons of an InputNumber.

The roles key on that exact class. A scope written with `!` (`![--ui-accent:…]`), a variant prefix (`hover:`, `md:`) or an inline `style` changes `--ui-accent` but keeps the roles of the component's own color, so a neutral soft, outline or ghost component, whose roles point at the surface tokens, ignores it. A custom color like `tertiary` has no role variables: set the role next to it instead, like `[--ui-accent-foreground:var(--ui-color-neutral-900)]`.

### Radius

`--ui-radius` is the base of Tailwind's `rounded-*` utilities, which Nuxt UI redefines in `@theme`:

```css
@theme {
  --radius-xs: calc(var(--ui-radius) * 0.5);
  --radius-sm: var(--ui-radius);
  --radius-md: calc(var(--ui-radius) * 1.5);
  --radius-lg: calc(var(--ui-radius) * 2);
  --radius-xl: calc(var(--ui-radius) * 3);
  --radius-2xl: calc(var(--ui-radius) * 4);
  --radius-3xl: calc(var(--ui-radius) * 6);
}
```

::warning
Changing `--ui-radius` also affects the `rounded-xs` to `rounded-3xl` classes on your own markup and third-party components, not only Nuxt UI components.
::

### Container

The [Container](/docs/components/container) component takes its max width from `--ui-container`. Point it at another size to change every container at once:

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

@theme {
  --container-8xl: 90rem;
}

:root {
  --ui-container: var(--container-8xl);
}
```

### Header

The [Header](/docs/components/header) component takes its height from `--ui-header-height`. [Main](/docs/components/main) and [Error](/docs/components/error) fill the viewport below it, and [PageAside](/docs/components/page-aside) sticks under it:

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

:root {
  --ui-header-height: --spacing(24);
}
```

## Fonts, breakpoints and motion

Fonts, breakpoints and easings are regular [Tailwind theme variables](https://tailwindcss.com/docs/theme): set `--font-*`, `--breakpoint-*` or `--ease-*` in `@theme` and Nuxt UI follows.

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

@theme {
  --font-sans: 'Public Sans', system-ui, sans-serif;
  --breakpoint-3xl: 1920px;
  --ease-out: cubic-bezier(0.16, 1, 0.3, 1);
}
```

::framework-only
#nuxt
:::note{to="/docs/getting-started/integrations/fonts"}
Fonts defined here are automatically loaded and optimized by the `@nuxt/fonts` module.
:::
::

Enter and exit animations run on `--ease-out`, indeterminate loading animations on `--ease-in-out`, so overriding these two retimes the library. When `prefers-reduced-motion` is set, overlays fade in place instead of scaling or sliding and movement transitions are disabled.

::tip
Tailwind CSS v4 changed its [Preflight](https://tailwindcss.com/docs/upgrade-guide#buttons-use-the-default-cursor) so that buttons use `cursor: default` instead of `cursor: pointer` to match browser defaults. If you'd like to restore the pointer cursor globally, add these base styles to your CSS:

```css [app/assets/css/main.css]
@layer base {
  button:not(:disabled),
  [role="button"]:not(:disabled) {
    cursor: pointer;
  }
}
```
::
