## Color system

Nuxt UI's colors are named after their **purpose** rather than their value. Components use `primary` or `error`, and you decide which palette each of them points at.

### Semantic colors

Each semantic color is an alias of a palette, any of the [default Tailwind CSS palettes](https://tailwindcss.com/docs/colors) or one you define:

| Color | Default | Used for |
| --- | --- | --- |
| `primary`{color="primary"} | `sky` | Main actions, active navigation, brand elements, links |
| `secondary`{color="secondary"} | `violet` | Secondary actions and complementary elements |
| `success`{color="success"} | `emerald` | Success messages and completed states |
| `info`{color="info"} | `blue` | Information and help |
| `warning`{color="warning"} | `amber` | Warnings and pending states |
| `error`{color="error"} | `red` | Errors, validation and destructive actions |
| `neutral` | `gray` | Text, borders, backgrounds and disabled states |

Use them in the `color` prop of the components:

::component-code{slug="button"}
---
props:
  color: primary
slots:
  default: Save Changes
---
::

Each color also gets Tailwind CSS utilities like `text-primary`, `bg-error` or `border-success-300`, see [CSS Variables](/docs/getting-started/theme/css-variables#colors).

::note
Try the :prose-icon{name="i-lucide-palette" class="text-primary"} theme menu in the header to see how other colors change the whole UI, or open the [theme editor](/theme) to customize everything at once.
::

### Configure colors

Point the aliases at other palettes with the `@nuxt/ui/colors` plugin in your `main.css`, after the imports. The aliases you leave out keep their default:

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

@plugin "@nuxt/ui/colors" {
  primary: blue;
  secondary: purple;
  neutral: zinc;
}
```

`neutral` also colors your text, backgrounds and borders, so `neutral: zinc` changes the whole page. To change only one of them, override its [CSS variable](/docs/getting-started/theme/css-variables#background).

To use your own palette, define every shade from `50` to `950` in `@theme` and give its name to the plugin:

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

@theme {
  --color-brand-50: #fef2f2;
  --color-brand-100: #fee2e2;
  --color-brand-200: #fecaca;
  --color-brand-300: #fca5a5;
  --color-brand-400: #f87171;
  --color-brand-500: #ef4444;
  --color-brand-600: #dc2626;
  --color-brand-700: #b91c1c;
  --color-brand-800: #991b1b;
  --color-brand-900: #7f1d1d;
  --color-brand-950: #450a0a;
}

@plugin "@nuxt/ui/colors" {
  primary: brand;
}
```

Overriding a Tailwind CSS palette in `@theme`, like `--color-sky-500`, also changes the aliases that use it.

::tip
The plugin reads the palettes from the stylesheet it's in. In one that doesn't import Tailwind CSS, like the stylesheet of a [Nuxt layer](https://nuxt.com/docs/getting-started/layers), import its theme first: `@import "tailwindcss/theme" theme(reference);`.
::

Each alias uses shade `500` in light mode and `400` in dark mode, `neutral` uses `900` and `50`. To use other shades, add both after the palette, light mode first. The palette is optional, and `black` and `white` work as shades too:

```css [app/assets/css/main.css]
@plugin "@nuxt/ui/colors" {
  /* Another palette, one shade darker in light mode */
  primary: indigo 600 400;
  /* Tailwind's neutral palette, a monochrome secondary */
  secondary: neutral 800 200;
  /* The default emerald, on other shades */
  success: 600 300;
  /* Black and white neutral solids */
  neutral: black white;
}
```

::note
An alias on a gray palette, like `primary: zinc`, or on the palette of `neutral`, is monochrome: its `soft`, `outline`, `subtle`, `ghost` and `link` variants look like `color="neutral"`.
::

### Change colors at runtime

The plugin sets the colors at build time. To change them at runtime, from a color picker or per tenant, set the shades of an alias on `:root`. The alias keeps the shades the plugin picked, now taken from the new palette:

::code-group

```ts [app/utils/palettes.ts]
// From https://tailwindcss.com/docs/colors
export const palettes: Record<string, Record<number, string>> = {
  indigo: {
    50: 'oklch(96.2% 0.018 272.314)',
    100: 'oklch(93% 0.034 272.788)',
    200: 'oklch(87% 0.065 274.039)',
    300: 'oklch(78.5% 0.115 274.713)',
    400: 'oklch(67.3% 0.182 276.935)',
    500: 'oklch(58.5% 0.233 277.117)',
    600: 'oklch(51.1% 0.262 276.966)',
    700: 'oklch(45.7% 0.24 277.023)',
    800: 'oklch(39.8% 0.195 277.366)',
    900: 'oklch(35.9% 0.144 278.697)',
    950: 'oklch(25.7% 0.09 281.288)'
  }
  // ...the other palettes your picker offers
}
```

```vue [app/app.vue]
<script setup lang="ts">
const primary = useState('primary', () => 'indigo')

useHead(() => ({
  style: [{
    innerHTML: `:root { ${Object.entries(palettes[primary.value] ?? {}).map(([shade, value]) => `--ui-color-primary-${shade}: ${value};`).join(' ')} }`,
    // After the stylesheets, so it also wins over your own unlayered `:root` rules
    tagPriority: 'low'
  }]
}))
</script>

<template>
  <UApp>
    <USelect v-model="primary" :items="Object.keys(palettes)" />
  </UApp>
</template>
```

::

Keep the palettes you offer in your own file, importing `tailwindcss/colors` would ship all of them to the browser.

::framework-only
#vue
:::note
Add `@unhead/vue` to your dependencies and import `useHead` from it, import `palettes` from your file, and keep the state in a `ref`.
:::
::

::warning
A value that comes from a database or a URL lands in a `<style>` tag. Check that it's a color first, like `/^#(?:[0-9a-f]{3,4}){1,2}$/i` for a hex color, or it can close the rule or the tag.
::

To give a part of the page its own colors, set the shades and the alias on it. The alias resolves on `:root`, so with the shades alone only utilities like `bg-primary-500` change:

```css [app/assets/css/main.css]
[data-theme='rose'] {
  --ui-color-primary-500: var(--color-rose-500);
  --ui-color-primary-400: var(--color-rose-400);
  --ui-primary: var(--ui-color-primary-500);
}

.dark [data-theme='rose'] {
  --ui-primary: var(--ui-color-primary-400);
}
```

::tip
For a single brand color without a palette, set the alias itself in both modes: `:root, .light, .dark { --ui-primary: #5647ff; }`. Components follow it, but shade utilities like `bg-primary-600` don't. `neutral` needs a full palette, since the page uses its shades.
::

### Extend colors

To use a color beyond the seven aliases, like a `tertiary` color, declare it in your `main.css` and bridge it to Tailwind CSS so it gets utilities like `bg-tertiary`:

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

@theme inline {
  --color-tertiary: var(--ui-tertiary);
}

:root {
  --ui-tertiary: var(--color-indigo-500);
}

.dark {
  --ui-tertiary: var(--color-indigo-400);
}
```

A component takes its color from `--ui-accent`, so point it at your color through `class`:

```vue
<template>
  <UButton class="[--ui-accent:var(--ui-tertiary)]" label="Special action" />
</template>
```

To use it through the `color` prop, add it to the `color` variant of each component, on the slot its theme scopes the color on. That's `base` for Button and `root` for Input:

::framework-only
#nuxt
:::div
```ts [app/app.config.ts]
export default defineAppConfig({
  ui: {
    button: {
      variants: {
        color: {
          tertiary: { base: '[--ui-accent:var(--ui-tertiary)]' }
        }
      }
    },
    input: {
      variants: {
        color: {
          tertiary: { root: '[--ui-accent:var(--ui-tertiary)]' }
        }
      }
    }
  }
})
```
:::

#vue
:::div
```ts [src/main.ts]
import ui from '@nuxt/ui/vue-plugin'

app.use(ui, {
  ui: {
    button: {
      variants: {
        color: {
          tertiary: { base: '[--ui-accent:var(--ui-tertiary)]' }
        }
      }
    },
    input: {
      variants: {
        color: {
          tertiary: { root: '[--ui-accent:var(--ui-tertiary)]' }
        }
      }
    }
  }
})
```
:::
::

`<UButton color="tertiary" />` then works like the built-in colors.

::framework-only
#nuxt
:::note
Nuxt UI adds the values from your `app.config.ts` to the component's prop types, so `color="tertiary"` type-checks too.
:::

#vue
:::note
The options of the Vue plugin aren't part of the prop types, so `color="tertiary"` works at runtime but fails type checking.
:::
::

::tip{to="/docs/getting-started/theme/css-variables#override-a-role"}
A custom color has none of the per-color variables the built-in ones have, like `--ui-primary-text-contrast`. Set the one you need next to it, like `[--ui-accent-text-contrast:var(--ui-color-neutral-900)]`.
::

## Tailwind CSS

Nuxt UI builds on Tailwind CSS, which uses a CSS-first configuration: you define your design tokens with the [`@theme`](https://tailwindcss.com/docs/functions-and-directives#theme-directive) directive in your CSS, and Nuxt UI follows them.

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

@theme {
  /* Your custom design tokens go here */
}
```

::note{to="https://tailwindcss.com/docs/theme" target="_blank"}
Check the Tailwind CSS documentation for all the theme variables you can customize.
::

### Fonts

Use the `--font-*` theme variables to [customize the font family utilities](https://tailwindcss.com/docs/font-family#customizing-your-theme) in your project:

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

@theme {
  --font-sans: 'Public Sans', system-ui, sans-serif;
  --font-heading: 'Outfit', var(--font-sans);
  --font-mono: 'JetBrains Mono', monospace;
}
```

Nuxt UI adds `--font-heading` to the theme, with a `font-heading` utility. It sets the font of the `h1` to `h6` elements and of the component titles, and headings keep the body font until you set it. The weights of the titles and of the body text have their own [CSS variables](/docs/getting-started/theme/css-variables#font).

::framework-only
#nuxt
:::note{to="/docs/getting-started/integrations/fonts"}
Fonts defined here are automatically loaded and optimized by the `@nuxt/fonts` module.
:::
::

### Breakpoints

Use the `--breakpoint-*` theme variables to [customize your breakpoints](https://tailwindcss.com/docs/responsive-design#customizing-your-theme):

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

@theme {
  --breakpoint-3xl: 1920px;
  --breakpoint-4xl: 2560px;
}
```

### Motion

Use the `--ease-*` theme variables to [customize the easing](https://tailwindcss.com/docs/transition-timing-function#customizing-your-theme) of animations and transitions. Enter and exit animations run on `--ease-out`, and the Toaster stack and the `swing` and `elastic` loading animations on `--ease-in-out`, so overriding these two retimes them across the library:

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

@theme {
  --ease-out: cubic-bezier(0.16, 1, 0.3, 1);
}
```

::note
When `prefers-reduced-motion` is set, overlays fade in place instead of scaling or sliding, and movement transitions are disabled.
::

### Cursor

Tailwind CSS v4 [gives buttons the default cursor](https://tailwindcss.com/docs/upgrade-guide#buttons-use-the-default-cursor), like browsers do. To bring back the pointer cursor everywhere, add these base styles to your CSS:

```css [app/assets/css/main.css]
@layer base {
  button:not(:disabled),
  [role="button"]:not(:disabled) {
    cursor: pointer;
  }
}
```
