## Override points

Every component is styled by a [theme](#theme-structure): classes for each slot, plus variants that add to them. You can override it at four levels, from the whole app down to one instance:

| Override | Scope | Takes |
| --- | --- | --- |
| [`<UTheme>`](#theme-component) | The components inside it, your whole app around `<UApp>` | Slot classes in `ui`, `variants`, prop defaults in `props`, `icons` and `unstyled` |
| [`app.config.ui`](#global-config) | Every instance in your app | `slots`, `variants`, `compoundVariants` and `defaultVariants` |
| [`ui` prop](#ui-prop) | One instance | Classes per slot |
| [`class` prop](#class-prop) | One instance | Classes for the root slot |

Classes apply in this order, and the last one wins a conflict:

1. The component's theme: its slot classes, `variants` and `compoundVariants`.
2. `app.config.ui`: its slot classes, then its `variants`, then its `compoundVariants`.
3. Each `<UTheme>` from the outermost to the closest: its slot classes, then its `variants`.
4. The `ui` prop.
5. The `class` prop.

Anything you set wins over the theme. Conflicting classes are merged, so `font-bold` replaces the theme's `font-medium` instead of sitting next to it.

::tip
The Theme section of each component page lists its slots and variants. You can also browse them in [`src/runtime/theme`](https://github.com/nuxt/ui/tree/v5/src/runtime/theme).
::

### Theme component

::framework-only
#nuxt
Wrap `<UApp>` in a [Theme](/docs/components/theme) in your `app.vue` to override components across your whole app:
#vue
Wrap `<UApp>` in a [Theme](/docs/components/theme) in your `App.vue` to override components across your whole app:
::

::framework-only
#nuxt
:::div
```vue [app/app.vue]
<script setup lang="ts">
const ui = {
  button: {
    base: 'font-bold'
  }
}

const variants = {
  button: {
    size: {
      md: {
        leadingIcon: 'size-4'
      }
    }
  }
}

const props = {
  button: {
    color: 'neutral',
    variant: 'outline'
  }
} as const
</script>

<template>
  <UTheme :ui="ui" :variants="variants" :props="props">
    <UApp>
      <NuxtPage />
    </UApp>
  </UTheme>
</template>
```
:::

#vue
:::div
```vue [App.vue]
<script setup lang="ts">
const ui = {
  button: {
    base: 'font-bold'
  }
}

const variants = {
  button: {
    size: {
      md: {
        leadingIcon: 'size-4'
      }
    }
  }
}

const props = {
  button: {
    color: 'neutral',
    variant: 'outline'
  }
} as const
</script>

<template>
  <UTheme :ui="ui" :variants="variants" :props="props">
    <UApp>
      <RouterView />
    </UApp>
  </UTheme>

```
:::
::

Every button gets `font-bold` and a `size-4` leading icon at the `md` size, and defaults to `color="neutral"` and `variant="outline"`. The Theme goes around `<UApp>` rather than inside it, so overlays and toasts get it too.

::tip{to="/docs/getting-started/theme/css-variables#control"}
To restyle a size, set its control variables rather than a padding, so the icon spacing and icon-only buttons follow.
::

### Global config

::framework-only
#nuxt
Your `app.config.ts` overrides components with the same structure as the theme itself. The Theme above reads like this there:
#vue
The `ui` option of your `vite.config.ts` overrides components with the same structure as the theme itself. The Theme above reads like this there:
::

::framework-only
#nuxt
:::div
```ts [app/app.config.ts]
export default defineAppConfig({
  ui: {
    button: {
      slots: {
        base: 'font-bold'
      },
      variants: {
        size: {
          md: {
            leadingIcon: 'size-4'
          }
        }
      },
      defaultVariants: {
        color: 'neutral',
        variant: 'outline'
      }
    }
  }
})
```
:::

#vue
:::div
```ts [vite.config.ts]
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      ui: {
        button: {
          slots: {
            base: 'font-bold'
          },
          variants: {
            size: {
              md: {
                leadingIcon: 'size-4'
              }
            }
          },
          defaultVariants: {
            color: 'neutral',
            variant: 'outline'
          }
        }
      }
    })
  ]
})
```
:::
::

`slots` takes the classes of `ui`, and `defaultVariants` the defaults of variant props like `color` and `size`. A Theme's `props` takes any prop.

::framework-only
#nuxt
:::note
Use the global config for what has to reach every page: `error.vue` renders in place of `app.vue`, so the Theme around `<UApp>` doesn't reach it. The variant values you add in `app.config.ts` are also added to the component's prop types, and it's where the [icon set](/docs/getting-started/integrations/icons/nuxt#theme) of your app goes, so ContentSearch uses it too.
:::

#vue
:::note
The variant values you add here aren't part of the prop types. It's where the [icon set](/docs/getting-started/integrations/icons/vue#theme) of your app goes.
:::
::

### `ui` prop

The `ui` prop overrides the slots of one instance, after every level above:

::component-code{slug="button"}
---
prettier: true
ignore:
  - ui.trailingIcon
  - color
  - variant
  - size
  - icon
props:
  trailingIcon: i-lucide-chevron-right
  size: md
  color: neutral
  variant: outline
  ui:
    trailingIcon: 'rotate-90 size-3'
slots:
  default: |

    Button
---
::

Here `size-3` wins over the icon size of `md`.

### `class` prop

The `class` prop overrides the root slot of one instance, `base` on Button. It applies last:

::component-code{slug="button"}
---
props:
  class: 'font-bold rounded-full'
slots:
  default: Button
---
::

::note
Components with a single element, like [Container](/docs/components/container), have one `root` slot, so `ui` and `class` reach the same element. [Icon](/docs/components/icon) has no `ui` prop, so use `class` to style it.
::

## Function slots

Set a slot to a function to replace its classes instead of adding to them. The function receives the classes it replaces, so you can keep part of them.

In `app.config.ui` or the `ui` of a Theme, it replaces the theme's classes for that slot. Variants and the classes of other levels still apply on top.

::note
A function slot runs once per configuration, so it should only depend on its argument.
::

::framework-only
#nuxt
:::div
```vue [app/app.vue]
<template>
  <UTheme :ui="{ button: { label: () => 'text-base font-bold' } }">
    <UApp>
      <NuxtPage />
    </UApp>
  </UTheme>
</template>
```
:::

:::warning
In `app.config.ts`, set a function slot in one place only. Nuxt merges the `app.config.ts` of every [layer](https://nuxt.com/docs/getting-started/layers) with `defuFn`, which calls your function and keeps its result, so Nuxt UI receives a plain string that adds to the defaults instead of replacing them.
:::

#vue
:::div
```vue [App.vue]
<template>
  <UTheme :ui="{ button: { label: () => 'text-base font-bold' } }">
    <UApp>
      <RouterView />
    </UApp>
  </UTheme>
</template>
```
:::

:::note
The options of `vite.config.ts` reach your app serialized, so a function slot there is dropped.
:::
::

In the `ui` prop, it receives the resolved classes, variants included, and its result is final. Only `class` still applies on top. On the root slot this also drops the `[--ui-accent:…]` class of the color, so keep it in what you return.

```vue
<template>
  <UButton :ui="{ label: () => 'text-base font-bold' }" label="Button" />
</template>
```

::tip{to="/docs/components/theme#unstyled"}
To remove the default classes from many components at once, wrap them in `<UTheme unstyled>`.
::

## Theme structure

Each component's theme lives in `src/runtime/theme` and declares its classes in four keys. The snippets below are abridged.

### Slots

`slots` holds the classes of each element of the component, and the `ui` prop takes the same keys. [Card](/docs/components/card) has one per section:

```ts [src/runtime/theme/card.ts]
export default {
  slots: {
    root: 'rounded-lg overflow-hidden',
    header: 'p-4 sm:px-6',
    title: 'text-strong font-semibold',
    description: 'mt-1 text-muted text-sm',
    body: 'p-4 sm:p-6',
    footer: 'p-4 sm:px-6'
  }
}
```

### Variants

`variants` adds classes to slots based on the component's props. [Avatar](/docs/components/avatar) sizes its `root` slot with a `size` variant:

```ts [src/runtime/theme/avatar.ts] {6-18}
export default {
  slots: {
    root: 'inline-flex items-center justify-center shrink-0 select-none rounded-full align-middle bg-accent-soft',
    image: 'h-full w-full rounded-[inherit] object-cover'
  },
  variants: {
    size: {
      sm: {
        root: 'size-7 text-sm'
      },
      md: {
        root: 'size-8 text-base'
      },
      lg: {
        root: 'size-9 text-lg'
      }
    }
  },
  defaultVariants: {
    size: 'md'
  }
}
```

### Default variants

`defaultVariants` sets the value of each variant when the prop isn't passed, like `size: 'md'` on Avatar above.

::tip{to="/docs/components/theme#default-variants"}
You can change the default `size` and `color` of every component that uses `md` and `primary` with the `'*'` key of `<UTheme :props>`.
::

### Compound variants

`compoundVariants` applies classes when several variant conditions match at once. [Chip](/docs/components/chip) uses them to move the chip onto the corner of its target, for each `position`, unless it is `inset`:

```ts [src/runtime/theme/chip.ts] {14-22}
export default {
  slots: {
    base: 'rounded-full ring ring-bg'
  },
  variants: {
    position: {
      'top-right': { base: 'top-0 right-0' },
      'bottom-right': { base: 'bottom-0 right-0' }
    },
    inset: {
      false: ''
    }
  },
  compoundVariants: [{
    position: 'top-right',
    inset: false,
    class: { base: '-translate-y-1/2 translate-x-1/2 transform' }
  }, {
    position: 'bottom-right',
    inset: false,
    class: { base: 'translate-1/2 transform' }
  }]
}
```
