## Override points

Every component is styled by a [theme](#theme-structure): classes per slot, changed by variants. You can override it at four points, from the whole app down to one instance:

| Override | Scope | Takes |
| --- | --- | --- |
| [`app.config.ui`](#global-config) | Every instance in your app | `slots`, `variants`, `compoundVariants` and `defaultVariants` |
| [`<UTheme>`](#theme-component) | The components inside it | Slot classes in `ui`, `variants`, prop defaults in `props`, `icons` and `unstyled` |
| [`ui` prop](#ui-prop) | One instance | Classes per slot |
| [`class` prop](#class-prop) | One instance | Classes for the root slot |

Classes apply in this order, and the last one wins a conflict:

1. The component's theme: its slot classes, `variants` and `compoundVariants`.
2. Each level of overrides, farthest first: `app.config.ui`, then each `<UTheme>` down to the component. Within a level, the same order as the theme: its slot classes, then its `variants`, then its `compoundVariants`.
3. The `ui` prop.
4. The `class` prop.

So anything you set wins over the theme, whatever form the theme rule takes. Nuxt UI merges the classes with [`cn`](https://github.com/shadcn-ui/cn), so `font-bold` replaces the theme's `font-medium` instead of sitting next to it.

::warning
This includes the compound variants that make room for an icon in Input or keep a `square` Button square: a padding you set for a `size` wins over them, so repeat the exception in your own `compoundVariants` if you need it.
::

::tip
The Theme section of each component page lists its slots and variants. You can also browse them in [`src/runtime/theme`](https://github.com/nuxt/ui/tree/v5/src/runtime/theme).
::

### Global config

::framework-only
#nuxt
Override the theme of a component for your whole app in your `app.config.ts`, with the same structure as the theme itself:
#vue
Override the theme of a component for your whole app in your `vite.config.ts`, with the same structure as the theme itself:
::

::framework-only
#nuxt
:::div
```ts [app/app.config.ts]
export default defineAppConfig({
  ui: {
    button: {
      slots: {
        base: 'font-bold'
      },
      variants: {
        size: {
          md: {
            leadingIcon: 'size-4'
          }
        }
      },
      compoundVariants: [{
        color: 'neutral',
        variant: 'outline',
        class: {
          base: 'ring-default hover:bg-strong'
        }
      }],
      defaultVariants: {
        color: 'neutral',
        variant: 'outline'
      }
    }
  }
})
```
:::

#vue
:::div
```ts [vite.config.ts]
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      ui: {
        button: {
          slots: {
            base: 'font-bold'
          },
          variants: {
            size: {
              md: {
                leadingIcon: 'size-4'
              }
            }
          },
          compoundVariants: [{
            color: 'neutral',
            variant: 'outline',
            class: {
              base: 'ring-default hover:bg-strong'
            }
          }],
          defaultVariants: {
            color: 'neutral',
            variant: 'outline'
          }
        }
      }
    })
  ]
})
```
:::
::

Here `font-bold` overrides `font-medium` on every button, `size-4` overrides `size-5` on the leading icon when `size="md"`, and `ring-default hover:bg-strong` overrides `ring-accent-strong hover:bg-accent-soft` when `color="neutral"` and `variant="outline"`. Buttons now default to `color="neutral"` and `variant="outline"`.

### Theme component

The [Theme](/docs/components/theme) component overrides slot classes, variants and prop defaults for the components inside it, without affecting the rest of your app. Its classes apply after your global config and any Theme around it:

### `ui` prop

The `ui` prop overrides the slots of one instance. It applies after the variants and every level of overrides:

::component-code{slug="button"}
---
prettier: true
ignore:
  - ui.trailingIcon
  - color
  - variant
  - size
  - icon
props:
  trailingIcon: i-lucide-chevron-right
  size: md
  color: neutral
  variant: outline
  ui:
    trailingIcon: 'rotate-90 size-3'
slots:
  default: |

    Button
---
::

Here `size-3` wins over the `size-5` the `md` size gives the trailing icon.

### `class` prop

The `class` prop overrides the root slot of one instance, `base` on Button. It applies last:

::component-code{slug="button"}
---
props:
  class: 'font-bold rounded-full'
slots:
  default: Button
---
::

::note
Components with a single element, like [Container](/docs/components/container), have one `root` slot, so `ui` and `class` reach the same element. [Icon](/docs/components/icon) has no `ui` prop, so use `class` to style it.
::

## Function slots

Set a slot to a function to replace its classes instead of adding to them. The function receives the classes it replaces, so you can keep part of them.

In `app.config.ui` or the `ui` of a Theme, it replaces the theme's classes for that slot. The `variants`, the `compoundVariants` and the plain classes other levels set on that slot still apply on top, even from a farther level.

::note
A function slot runs once per configuration, so it should only depend on its argument.
::

::framework-only
#nuxt
:::div
```ts [app/app.config.ts]
export default defineAppConfig({
  ui: {
    button: {
      slots: {
        label: () => 'text-base font-bold'
      }
    }
  }
})
```
:::

#vue
:::div
The options of `vite.config.ts` reach your app serialized, so a function there is dropped. Set it on a `UTheme` around `UApp` instead, so overlays and toasts get it too:

```vue [App.vue]
<template>
  <UTheme :ui="{ button: { label: () => 'text-base font-bold' } }">
    <UApp>
      <RouterView />
    </UApp>
  </UTheme>
</template>
```
:::
::

In the `ui` prop of a component, it receives the classes the slot resolved to, variants included, and its result is final: only the `class` prop still applies on top, on the root slot. On the slot that carries the color, usually the root, that also drops the `[--ui-accent:…]` class, so keep it in what you return.

```vue
<template>
  <UButton :ui="{ label: () => 'text-base font-bold' }" label="Button" />
</template>
```

::framework-only
#nuxt
:::warning
Set a slot to a function in one place only. Nuxt merges the `app.config.ts` of every [layer](https://nuxt.com/docs/getting-started/layers) with `defuFn`, which calls your function with whatever value the key already has lower down and keeps only the result. Nuxt UI then reads a plain string, so its classes are merged onto the defaults instead of replacing them.
:::
::

::tip{to="/docs/components/theme#unstyled"}
To remove the default classes from many components at once, wrap them in `<UTheme unstyled>`, or set `ui.unstyled` app-wide.
::

## Theme structure

Each component's theme lives in `src/runtime/theme` and declares its classes in four keys. The snippets below are abridged.

### Slots

`slots` holds the classes of each element of the component, and the `ui` prop takes the same keys. [Card](/docs/components/card) has one per section:

```ts [src/runtime/theme/card.ts]
export default {
  slots: {
    root: 'rounded-lg overflow-hidden',
    header: 'p-4 sm:px-6',
    title: 'text-strong font-semibold',
    description: 'mt-1 text-muted text-sm',
    body: 'p-4 sm:p-6',
    footer: 'p-4 sm:px-6'
  }
}
```

### Variants

`variants` adds classes to slots based on the component's props. [Avatar](/docs/components/avatar) sizes its `root` slot with a `size` variant:

```ts [src/runtime/theme/avatar.ts] {6-18}
export default {
  slots: {
    root: 'inline-flex items-center justify-center shrink-0 select-none rounded-full align-middle bg-accent-soft',
    image: 'h-full w-full rounded-[inherit] object-cover'
  },
  variants: {
    size: {
      sm: {
        root: 'size-7 text-sm'
      },
      md: {
        root: 'size-8 text-base'
      },
      lg: {
        root: 'size-9 text-lg'
      }
    }
  }
}
```

---
ignore:
  - src
props:
  src: 'https://github.com/nuxt.png'

### Default variants

Each variant prop has a default, like `size: 'md'` on Avatar above, listed in the component's API. `defaultVariants` in your `app.config.ts` or `vite.config.ts` changes it for every instance.

::tip{to="/docs/components/theme#default-variants"}
You can change the default `size` and `color` of every component that uses `md` and `primary` with the `'*'` key of `<UTheme :props>`, or app-wide with `ui.defaultVariants`.
::

### Compound variants

`compoundVariants` applies classes when several variant conditions match at once. [Button](/docs/components/button) uses one to change the padding of a `square` button for each `size`:

```ts [src/runtime/theme/button.ts] {14-18}
export default {
  slots: {
    base: 'rounded-md font-medium inline-flex items-center'
  },
  variants: {
    size: {
      xs: { base: 'px-2 py-1 text-xs gap-1' },
      md: { base: 'px-2.5 py-1.5 text-sm gap-1.5' }
    },
    square: {
      true: ''
    }
  },
  compoundVariants: [{
    size: 'xs',
    square: true,
    class: { base: 'p-1' }
  }]
}
```
