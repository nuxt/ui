Every token is a CSS variable behind a Tailwind utility. `neutral-400` below stands for `var(--ui-color-neutral-400)`, so the surfaces follow the palette of `neutral`.

| Token | Light | Dark | Used for |
| --- | --- | --- | --- |
| `--ui-primary`, `--ui-secondary`, `--ui-success`, `--ui-info`, `--ui-warning`, `--ui-error` | Shade `500` | Shade `400` | `text-primary`, `bg-error`… |
| `--ui-neutral` | Shade `900` | Shade `50` | `text-neutral`, `bg-neutral`… |
| `--ui-text-highlighted` | `neutral-900` | `white` | `text-highlighted`, titles |
| `--ui-text-default` | `neutral-700` | `neutral-200` | `text-default`, body text |
| `--ui-text-muted` | `neutral-500` | `neutral-400` | `text-muted`, descriptions |
| `--ui-text-faint` | `neutral-400` | `neutral-500` | `text-faint`, placeholders |
| `--ui-text-inverted` | `white` | `neutral-900` | `text-inverted`, text on an inverted background |
| `--ui-bg-surface` | `white` | `neutral-900` | `bg-surface`, the page |
| `--ui-bg-soft` | `neutral-100` | `neutral-800` | `bg-soft`, raised surfaces |
| `--ui-bg-soft-hover` | `neutral-200` | `neutral-700` | `bg-soft-hover`, the hover of a raised surface |
| `--ui-bg-tint` | Unset: `--ui-bg-soft` at 50% | Same | `bg-tint`, hovered and highlighted items |
| `--ui-bg-muted` | `neutral-50` | `neutral-800` | `bg-muted` |
| `--ui-bg-inverted` | `neutral-900` | `white` | `bg-inverted`, an inverted surface |
| `--ui-border-default` | `neutral-200` | `neutral-800` | `border-default` |
| `--ui-border-muted` | `neutral-200` | `neutral-700` | `border-muted`, a border on a `bg-soft` or `bg-muted` fill, like a code block |
| `--ui-border-strong` | `neutral-300` | `neutral-700` | `border-strong`, field outlines |
| `--ui-border-inverted` | `neutral-900` | `white` | `border-inverted` |
| `--ui-focus` | Unset: `--ui-primary` at 25% | Same | `outline-focus`, the focus outline |
| `--ui-accent-foreground` | `--ui-text-inverted` | Same | `text-accent-foreground`, text on a solid accent background |
| `--ui-accent-hover` | `--ui-accent` at 75% | Same | `bg-accent-hover`, the hover of a solid background |
| `--ui-accent-surface` | `transparent` | Same | `bg-accent-surface`, the background of an outline variant |
| `--ui-accent-soft` | `--ui-accent` at 10% | Same | `bg-accent-soft`, a tinted background |
| `--ui-accent-soft-hover` | `--ui-accent` at 15% | Same | `bg-accent-soft-hover`, the hover of a tinted background |
| `--ui-accent-soft-foreground` | `--ui-accent` | Same | `text-accent-soft-foreground`, text on a tinted background |
| `--ui-accent-tint` | `--ui-accent` at 5% | Same | `bg-accent-tint`, hovered and highlighted items |
| `--ui-accent-muted` | `--ui-accent` | Same | `text-accent-muted`, the text of a link variant |
| `--ui-accent-muted-hover` | `--ui-accent` at 75% | Same | `text-accent-muted-hover`, its hover |
| `--ui-accent-faint` | `--ui-accent` at 75% | Same | `text-accent-faint`, icons next to a label |
| `--ui-accent-border` | `--ui-accent` at 25% | Same | `ring-accent-border`, a colored border |
| `--ui-accent-border-strong` | `--ui-accent` at 50% | Same | `ring-accent-border-strong`, a stronger colored border |
| `--ui-accent-focus` | `--ui-accent` at 25% | Same | `outline-accent-focus`, the focus outline |
| `--ui-radius` | `0.25rem` | Same | The base of the [`rounded-*` scale](#radius) |
| `--ui-container` | `80rem` | Same | The max width of [Container](#container) |
| `--ui-header-height` | `4rem` | Same | The height of [Header](#header) |

The border tokens also work with `ring-*` and `divide-*`. `ring-surface`, `border-surface`, `fill-surface` and `stroke-surface` use the page background, like the ring that sets an avatar apart from the one below it, and `bg-border` fills an element with the border color, like a separator. Every accent role works with any color utility, like `text-accent` or `border-accent-border`. A role that shares a word with a surface token is its colored counterpart: `bg-soft` is always neutral, `bg-accent-soft` follows `color`.

Override a token in your `main.css`. A value on `:root` applies in both modes, and one on `.dark` takes over in dark mode:

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

:root {
  --ui-bg-surface: var(--ui-color-neutral-50);
}

.dark {
  --ui-bg-surface: var(--ui-color-neutral-950);
}
```

To change all the surfaces at once, [give `neutral` another palette](/docs/getting-started/theme/design-system#configure-colors) instead.

## Accent

The `color` prop puts a class like `[--ui-accent:var(--ui-primary)]` on the component. That class also points each accent role at a variable of the color, `--ui-primary-soft`, `--ui-primary-foreground` and so on. They are unset by default, so the roles take the values in the table. Set one to change a role of one color, and every component follows. For example, dark text on a yellow `warning`:

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

:root {
  --ui-warning-foreground: var(--ui-color-neutral-900);
}
```

`neutral` points most of these roles at the surface token of the same word instead, `--ui-accent-soft` at `--ui-bg-soft` or `--ui-accent-border-strong` at `--ui-border-strong`, which is how a neutral component keeps its look. The others differ: `border` is `--ui-border-muted`, since it usually sits on a fill, `hover` is the neutral color at 90%, and `soft-foreground` and `muted-hover` are `--ui-text-default`. Its focus is the exception: it stays the neutral color at 25%, not `--ui-focus`. `--ui-neutral-soft` and the other `--ui-neutral-<role>` variables override them the same way. `color="neutral"` uses the same classes as every other color, except in Callout, inline Code, Calendar, ChatMessage and Separator.

The accent utilities work in your own markup too. Set `--ui-accent` through a class to pick the color:

```vue
<template>
  <div class="[--ui-accent:var(--ui-error)] bg-accent-soft text-accent-soft-foreground">
    Something went wrong
  </div>
</template>
```

The same class recolors a component outside its `color` prop, like `<UButton class="[--ui-accent:var(--color-indigo-500)]" />`. A few parts set their own and take it through `ui` instead: items with their own color in DropdownMenu and ContextMenu, the segments of a ProgressGroup, the links of a NavigationMenu, the loading bar of a Table (`loading-color`), the indicator of a Timeline and the dot of a Chip. Components nested inside keep their own color too, like the buttons of an InputNumber.

The roles key on that exact class. A scope written with `!` (`![--ui-accent:…]`), a variant prefix (`hover:`, `md:`) or an inline `style` changes `--ui-accent` but keeps the roles of the component's own color, so a neutral soft, outline or ghost component, whose roles point at the surface tokens, ignores it apart from its focus styles. A custom color like `tertiary` has no role variables: set the role next to it instead, like `[--ui-accent-foreground:var(--ui-color-neutral-900)]`.

## Radius

`--ui-radius` is the base of Tailwind's `rounded-*` utilities, which Nuxt UI redefines in `@theme`:

```css
@theme default inline {
  --radius-xs: calc(var(--ui-radius) * 0.5);
  --radius-sm: var(--ui-radius);
  --radius-md: calc(var(--ui-radius) * 1.5);
  --radius-lg: calc(var(--ui-radius) * 2);
  --radius-xl: calc(var(--ui-radius) * 3);
  --radius-2xl: calc(var(--ui-radius) * 4);
  --radius-3xl: calc(var(--ui-radius) * 6);
}
```

::warning
Changing `--ui-radius` also affects the `rounded-xs` to `rounded-3xl` classes on your own markup and third-party components, not only Nuxt UI components.
::

## Container

The [Container](/docs/components/container) component takes its max width from `--ui-container`. Point it at another size to change every container at once:

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

@theme {
  --container-8xl: 90rem;
}

:root {
  --ui-container: var(--container-8xl);
}
```

## Header

The [Header](/docs/components/header) component takes its height from `--ui-header-height`. [Main](/docs/components/main) and [Error](/docs/components/error) fill the viewport below it, and [PageAside](/docs/components/page-aside) sticks under it:

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

:root {
  --ui-header-height: --spacing(24);
}
```

## Default CSS

These are the values Nuxt UI ships in `@nuxt/ui/base`. The palettes, aliases and tokens sit in `@layer base` at zero specificity, so the `@nuxt/ui/colors` plugin and your own `:root` rules win over them. The `@theme inline` block of `@nuxt/ui/sources` turns each token into its utilities, like `--ui-bg-soft` into `bg-soft`.
