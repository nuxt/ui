Each token is a CSS variable, most of them with a Tailwind utility. The surface tokens are shades of `neutral`, one per mode.

In the table, `neutral-400` stands for `var(--ui-color-neutral-400)`.

| Token | Light | Dark | Used for |
| --- | --- | --- | --- |
| `--ui-primary`, `--ui-secondary`, `--ui-success`, `--ui-info`, `--ui-warning`, `--ui-error` | Shade `500` | Shade `400` | `text-primary`, `bg-error`… |
| `--ui-neutral` | Shade `900` | Shade `50` | `bg-neutral`, `border-neutral`…, the neutral solid |
| `--ui-neutral-bg-hover` | Unset: `--ui-neutral` at 90% | Same | `bg-neutral-hover`, the hover of the neutral solid |
| `--ui-text-strong` | `neutral-900` | `white` | `text-strong`, titles |
| `--ui-text-default` | `neutral-700` | `neutral-200` | `text-default`, body text |
| `--ui-text-muted` | `neutral-500` | `neutral-400` | `text-muted`, descriptions |
| `--ui-text-faint` | `neutral-400` | `neutral-500` | `text-faint`, placeholders |
| `--ui-text-contrast` | `white` | `neutral-900` | `text-contrast`, text on a solid |
| `--ui-bg-default` | `white` | `neutral-900` | `bg-default`, the page |
| `--ui-bg-tint` | Unset: `--ui-bg-soft` at 50% | Same | `bg-tint`, the lightest fill: hovered items, code blocks, table heads |
| `--ui-bg-backdrop` | Unset: `--ui-bg-soft` at 75% | Same | `bg-backdrop`, the layer behind a Modal, a Slideover and a Drawer |
| `--ui-bg-soft` | `neutral-100` | `neutral-800` | `bg-soft`, soft fills and raised areas |
| `--ui-bg-strong` | `neutral-200` | `neutral-700` | `bg-strong`, strong fills like a track, and the hover of `bg-soft` |
| `--ui-border-default` | `neutral-200` | `neutral-800` | `border-default` |
| `--ui-border-strong` | `neutral-300` | `neutral-700` | `border-strong`, field outlines |
| `--ui-outline-focus` | Unset: `--ui-primary` at 25% | Same | `outline-focus`, the focus outline of components without a `color` prop |
| `--ui-radius` | `0.25rem` | Same | The base of the [`rounded-*` scale](#radius) |
| `--ui-container` | `80rem` | Same | The max width of [Container](#container) |
| `--ui-header-height` | `4rem` | Same | The height of [Header](#header) |

An unset token has no value to read: `var(--ui-bg-tint)` in your own CSS resolves to nothing until you set it. Use its utility, `bg-tint`, which holds the fallback.

The border tokens also work with `ring-*`, `ring-offset-*` and `divide-*`, and `default` with `outline-*`, `fill-*` and `stroke-*`. `ring-bg`, `border-bg`, `fill-bg` and `stroke-bg` use the page background, like the ring that sets an avatar apart from the one below it, and `bg-border` fills an element with the border color, like a separator.

Override a token in your `main.css`. A value on `:root` applies in both modes, and one on `.dark` takes over in dark mode:

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

:root {
  --ui-bg-default: var(--ui-color-neutral-50);
}

.dark {
  --ui-bg-default: var(--ui-color-neutral-950);
}
```

To change all the surfaces at once, [give `neutral` another palette](/docs/getting-started/theme/design-system#configure-colors) instead.

## Accent

The `color` prop sets `--ui-accent` on a component, and its classes read the accent roles of that color. Each role is a neutral token with `accent-` in front, and `color="neutral"` resolves it to that token. Three roles differ under neutral: `bg-accent-hover` is `--ui-neutral` at 90%, `bg-accent-strong` is `--ui-bg-strong` at 75%, and `outline-accent-focus` is `--ui-neutral` at 25%.

| Role | Utility | Colors | `color="neutral"` |
| --- | --- | --- | --- |
| `--ui-accent` | `bg-accent`, `border-accent`… | The color | `--ui-neutral` |
| `--ui-accent-bg-hover` | `bg-accent-hover` | The color at 75% | `--ui-neutral` at 90% |
| `--ui-accent-bg-tint` | `bg-accent-tint` | The color at 5% | `--ui-bg-tint` |
| `--ui-accent-bg-soft` | `bg-accent-soft` | The color at 10% | `--ui-bg-soft` |
| `--ui-accent-bg-strong` | `bg-accent-strong` | The color at 15% | `--ui-bg-strong` at 75% |
| `--ui-accent-text-strong` | `text-accent-strong`, `text-accent` | The `default` text | `--ui-text-strong` |
| `--ui-accent-text-default` | `text-accent-default` | The color | `--ui-text-default` |
| `--ui-accent-text-muted` | `text-accent-muted` | The `default` text at 75% | `--ui-text-muted` |
| `--ui-accent-text-faint` | `text-accent-faint` | The `default` text at 50% | `--ui-text-faint` |
| `--ui-accent-text-contrast` | `text-accent-contrast` | `--ui-text-contrast` | `--ui-text-contrast` |
| `--ui-accent-border-default` | `border-accent-default`, `ring-accent-default`, `divide-accent-default` | The color at 25% | `--ui-border-default` |
| `--ui-accent-border-strong` | `border-accent-strong`, `ring-accent-strong`, `divide-accent-strong` | The color at 50% | `--ui-border-strong` |
| `--ui-accent-outline-focus` | `outline-accent-focus` | The color at 25% | `--ui-neutral` at 25% |

A role only exists on the properties it's meant for: `bg-accent-soft` works, `text-accent-soft` doesn't. `--ui-accent` itself works with any color utility.

### Override a role

Each color has a variable per role, like `--ui-warning-bg-soft` or `--ui-warning-text-contrast`, unset by default. Set one to change that role for one color in every component, like dark text on a yellow `warning`:

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

:root {
  --ui-warning-text-contrast: var(--ui-color-neutral-900);
}
```

`--ui-neutral-<role>` works the same for neutral.

### Colored text

`text-primary`, `text-accent` and the labels of the `soft`, `subtle`, `outline`, `ghost` and `link` variants use `--ui-<color>-text-default`, which is the color itself by default. Set it to change the text of a color everywhere without touching its solid. The `strong`, `muted` and `faint` steps follow it.

At shade `500`, `primary`, `success` and `warning` text is under 3:1 on white. To darken the text in light mode and keep the solids:

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

:root {
  --ui-primary-text-default: var(--ui-color-primary-700);
}

.dark {
  --ui-primary-text-default: initial;
}
```

These shades reach 4.5:1 for the default colors, on the page and on soft fills:

| Color | Shade |
| --- | --- |
| `primary`{color="primary"} | `700` |
| `secondary`{color="secondary"} | `600` |
| `success`{color="success"} | `700` |
| `info`{color="info"} | `700` |
| `warning`{color="warning"} | `800` |
| `error`{color="error"} | `700` |

::note
`--ui-<color>-text-muted` sets the muted step alone, used by the `link` Button and the Avatar fallback. Set it to the same shade for those to reach 4.5:1 too.
::

### Outside a component

The accent utilities work in your own markup too. Set `--ui-accent` through a class to pick the color:

```vue
<template>
  <div class="[--ui-accent:var(--ui-error)] bg-accent-soft text-accent-default">
    Something went wrong
  </div>
</template>
```

The same class recolors a component outside its `color` prop, like `<UButton class="[--ui-accent:var(--color-indigo-500)]" />`.

::warning
The roles follow that exact class. With `!`, a variant like `hover:` or an inline `style`, only `--ui-accent` changes, not the roles the class sets, so a neutral component keeps its neutral fills, text and borders.
::

Some parts set their own `--ui-accent`, so change them through `ui` instead: colored items in DropdownMenu and ContextMenu, ProgressGroup segments, NavigationMenu links, the Table loading bar, the Timeline indicator and the Chip dot. Nested components keep their own color, like the buttons of an InputNumber.

## Chart :badge{label="4.12+" class="align-text-top"}

The [Chart](/docs/components/chart) component paints its series with six CSS variables, in order. The first one follows your `primary` color:

::code-group

```css [Light]
:root {
  --ui-chart-1: var(--ui-primary);
  --ui-chart-2: var(--color-blue-500);
  --ui-chart-3: var(--color-violet-500);
  --ui-chart-4: var(--color-amber-500);
  --ui-chart-5: var(--color-rose-500);
  --ui-chart-6: var(--color-cyan-500);
}
```

```css [Dark]
.dark {
  --ui-chart-1: var(--ui-primary);
  --ui-chart-2: var(--color-blue-400);
  --ui-chart-3: var(--color-violet-400);
  --ui-chart-4: var(--color-amber-400);
  --ui-chart-5: var(--color-rose-400);
  --ui-chart-6: var(--color-cyan-400);
}
```

::

Override them in your `main.css`:

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

:root {
  --ui-chart-2: var(--color-teal-500);
}

.dark {
  --ui-chart-2: var(--color-teal-400);
}
```

## Control

Buttons, badges, fields and the links of a NavigationMenu write their dimensions as variables, per `size` where they have one, and their classes read them:

| Variable | Used for | `md` on a Button |
| --- | --- | --- |
| `--ui-control-px` | Horizontal padding | `--spacing(2.5)` |
| `--ui-control-py` | Vertical padding | `--spacing(1.5)` |
| `--ui-control-gap` | Gap between an icon and the label | `--spacing(1.5)` |
| `--ui-control-icon` | Size of the leading and trailing icons | `--spacing(5)` |
| `--ui-control-text-step` | Added to the text size of a field, except at the `xl` size | `0px` |

Set them to restyle a size. A field spaces its icon with the padding and the gap, and an icon-only button uses the vertical padding on every side, so both follow:

```ts [app.config.ts]
export default defineAppConfig({
  ui: {
    button: {
      variants: {
        size: {
          md: { base: '[--ui-control-px:--spacing(4)] [--ui-control-py:--spacing(2)]' }
        }
      }
    }
  }
})
```

The variables sit on the outermost element, where `class` lands. That's `root` on Input, InputNumber, InputMenu, InputTags, InputDate, InputTime, Textarea, Checkbox, RadioGroup, Calendar and FileUpload, and `base` on the other controls, Select and SelectMenu included. NavigationMenu writes them on each `link` and `label`. Checkbox and RadioGroup only write the padding of their `card` and `table` items and the icon size.

Set them through `class` to change one instance:

```vue
<UInput icon="i-lucide-search" class="[--ui-control-icon:--spacing(4)]" />
```

A field has the same text size on every screen. iOS Safari zooms on a focused field whose text is under 16px, so you can make fields larger on small screens with `--ui-control-text-step`. With the value below, `md` and `lg` fields reach 16px:

```css [app/assets/css/main.css]
@media (width < 48rem) {
  :root {
    --ui-control-text-step: 0.125rem;
  }
}
```

The `square` prop sets the horizontal padding to the vertical one. Button, Badge and NavigationMenu have it, and it follows a size you restyle:

```vue
<UNavigationMenu :items="items" orientation="vertical" square />
```

Slider, Progress, ProgressGroup and Separator write a single variable on their `root`, `--ui-control-thickness`: the height of the track or the width of the line, read as a height or a width depending on `orientation`.

```vue
<UProgress :model-value="50" class="[--ui-control-thickness:--spacing(1.5)]" />
```

Calendar writes `--ui-control-size`, the size of a day cell and the height of a month or year cell, with `--ui-control-px` for the padding of the latter.

Timeline and Stepper write `--ui-control-size` too, the size of the indicator and of the trigger, and derive the offsets of their separators from it. FileUpload writes the four variables of a field for its files.

::note
A size you add in your app config needs the variables too to work with `square`, an icon or `orientation`. A plain padding like `px-4` on a Button still wins over the theme, so restyle a size through the variables to keep icon-only buttons square.
::

## Radius

`--ui-radius` is the base of Tailwind's `rounded-*` utilities, which Nuxt UI redefines in `@theme`:

```css
@theme default inline {
  --radius-xs: calc(var(--ui-radius) * 0.5);
  --radius-sm: var(--ui-radius);
  --radius-md: calc(var(--ui-radius) * 1.5);
  --radius-lg: calc(var(--ui-radius) * 2);
  --radius-xl: calc(var(--ui-radius) * 3);
  --radius-2xl: calc(var(--ui-radius) * 4);
  --radius-3xl: calc(var(--ui-radius) * 6);
}
```

::warning
Changing `--ui-radius` also affects the `rounded-xs` to `rounded-3xl` classes on your own markup and third-party components, not only Nuxt UI components.
::

## Container

The [Container](/docs/components/container) component takes its max width from `--ui-container`. Point it at another size to change every container at once:

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

@theme {
  --container-8xl: 90rem;
}

:root {
  --ui-container: var(--container-8xl);
}
```

## Header

The [Header](/docs/components/header) component takes its height from `--ui-header-height`. [Main](/docs/components/main) and [Error](/docs/components/error) fill the viewport below it, and [PageAside](/docs/components/page-aside) sticks under it:

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

:root {
  --ui-header-height: --spacing(24);
}
```

## Default CSS

[`base.css`](https://github.com/nuxt/ui/blob/v5/src/runtime/css/base.css), imported by `@nuxt/ui`, holds the defaults of the tokens. [`tokens.css`](https://github.com/nuxt/ui/blob/v5/src/runtime/css/tokens.css) holds the recipes of the unset tokens and the accent roles, like `bg-tint` at 50% of `bg-soft`. The control values come from the theme of each component. The `@nuxt/ui/colors` plugin and your own `:root` rules win over the defaults of `base.css`, unless you put them in `@layer theme`.
