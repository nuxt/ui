Each token is a CSS variable, most of them behind a Tailwind utility. `neutral-400` below stands for `var(--ui-color-neutral-400)`, so the surfaces follow the palette of `neutral`.

| Token | Light | Dark | Used for |
| --- | --- | --- | --- |
| `--ui-primary`, `--ui-secondary`, `--ui-success`, `--ui-info`, `--ui-warning`, `--ui-error` | Shade `500` | Shade `400` | `text-primary`, `bg-error`… |
| `--ui-neutral` | Shade `900` | Shade `50` | `bg-neutral`, `border-neutral`…, the neutral solid |
| `--ui-neutral-bg-hover` | Unset: `--ui-neutral` at 90% | Same | `bg-neutral-hover`, the hover of the neutral solid |
| `--ui-text-strong` | `neutral-900` | `white` | `text-strong`, titles |
| `--ui-text-default` | `neutral-700` | `neutral-200` | `text-default`, body text |
| `--ui-text-muted` | `neutral-500` | `neutral-400` | `text-muted`, descriptions |
| `--ui-text-faint` | `neutral-400` | `neutral-500` | `text-faint`, placeholders |
| `--ui-text-contrast` | `white` | `neutral-900` | `text-contrast`, text on a solid |
| `--ui-bg-default` | `white` | `neutral-900` | `bg-default`, the page |
| `--ui-bg-tint` | Unset: `--ui-bg-soft` at 50% | Same | `bg-tint`, the lightest fill: hovered items, code blocks, table heads |
| `--ui-bg-backdrop` | Unset: `--ui-bg-soft` at 75% | Same | `bg-backdrop`, the layer behind a Modal, a Slideover and a Drawer |
| `--ui-bg-soft` | `neutral-100` | `neutral-800` | `bg-soft`, soft fills and raised areas |
| `--ui-bg-strong` | `neutral-200` | `neutral-700` | `bg-strong`, strong fills like a track, and the hover of `bg-soft` |
| `--ui-border-default` | `neutral-200` | `neutral-800` | `border-default` |
| `--ui-border-strong` | `neutral-300` | `neutral-700` | `border-strong`, field outlines |
| `--ui-outline-focus` | Unset: `--ui-primary` at 25% | Same | `outline-focus`, the focus outline of components without a `color` prop |
| `--ui-radius` | `0.25rem` | Same | The base of the [`rounded-*` scale](#radius) |
| `--ui-container` | `80rem` | Same | The max width of [Container](#container) |
| `--ui-header-height` | `4rem` | Same | The height of [Header](#header) |

An unset token has no value to read: `var(--ui-bg-tint)` in your own CSS resolves to nothing until you set it. Use its utility, `bg-tint`, which holds the fallback.

The border tokens also work with `ring-*`, `ring-offset-*` and `divide-*`, and `default` with `outline-*`, `fill-*` and `stroke-*`. `ring-bg`, `border-bg`, `fill-bg` and `stroke-bg` use the page background, like the ring that sets an avatar apart from the one below it, and `bg-border` fills an element with the border color, like a separator.

Override a token in your `main.css`. A value on `:root` applies in both modes, and one on `.dark` takes over in dark mode:

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

:root {
  --ui-bg-default: var(--ui-color-neutral-50);
}

.dark {
  --ui-bg-default: var(--ui-color-neutral-950);
}
```

To change all the surfaces at once, [give `neutral` another palette](/docs/getting-started/theme/design-system#configure-colors) instead.

## Accent

The `color` prop puts a class like `[--ui-accent:var(--ui-primary)]` on the component. That class also points each accent role at a variable of the color, `--ui-primary-bg-soft`, `--ui-primary-text-contrast` and so on. They are unset by default, so the roles take the values in the table. Set one to change a role of one color, and every component follows. For example, dark text on a yellow `warning`:

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

:root {
  --ui-warning-text-contrast: var(--ui-color-neutral-900);
}
```

| Role | Utility | Colors | `color="neutral"` |
| --- | --- | --- | --- |
| `--ui-accent` | `bg-accent`, `text-accent`, `border-accent`… | The color | `--ui-neutral` |
| `--ui-accent-bg-hover` | `bg-accent-hover` | The color at 75% | `--ui-neutral` at 90%, `bg-neutral-hover` |
| `--ui-accent-bg-tint` | `bg-accent-tint` | The color at 5% | `--ui-bg-tint` |
| `--ui-accent-bg-soft` | `bg-accent-soft` | The color at 10% | `--ui-bg-soft` |
| `--ui-accent-bg-strong` | `bg-accent-strong` | The color at 15% | `--ui-bg-strong` at 75% |
| `--ui-accent-text-default` | `text-accent-default` | The color | `--ui-text-default` |
| `--ui-accent-text-contrast` | `text-accent-contrast` | `--ui-text-contrast` | `--ui-text-contrast` |
| `--ui-accent-text-muted` | `text-accent-muted` | The color at 75% | `--ui-text-muted` |
| `--ui-accent-text-faint` | `text-accent-faint` | The color at 50% | `--ui-text-faint` |
| `--ui-accent-border-default` | `border-accent-default`, `ring-accent-default`, `divide-accent-default` | The color at 25% | `--ui-border-default` |
| `--ui-accent-border-strong` | `border-accent-strong`, `ring-accent-strong`, `divide-accent-strong` | The color at 40% | `--ui-border-strong` |
| `--ui-accent-outline-focus` | `outline-accent-focus` | The color at 25% | `--ui-neutral` at 25% |

A role resolves on the element, in this order:

1. The variable of the color, like `--ui-warning-text-default`, when you set it. `--ui-neutral-<role>` works the same for neutral.
2. For `color="neutral"`, the neutral token of the same name, like `--ui-bg-soft` for `--ui-accent-bg-soft`, which is how a neutral component keeps its look. The focus stays the neutral color at 25%, like every color focuses in its own, where `outline-focus` is `primary`. One more role differs, to keep v4's look: the hover of a soft fill is `bg-strong` at 75%.
3. Otherwise the value in the table, mixed from `--ui-accent`, or from the `default` text step for `muted` and `faint`.

Each step reads the light or dark value of what it points at, `--ui-primary` being shade `500` in light mode and `400` in dark mode for example, so a role follows the mode without a value of its own. A role you set on `:root` applies in both modes, and one on `.dark` takes over in dark mode.

The raw name is the solid on every property, `bg-accent`, `ring-accent` and `text-accent`, with `text-accent-contrast` on it, and `bg-neutral` with `text-contrast` for neutral. Each step is a role. `--ui-<color>-text-default` changes the text of one color without touching its solid, and its `muted` and `faint` steps follow, like a darker `warning` text on a light background: `--ui-warning-text-default: var(--ui-color-warning-700)`. `color="neutral"` uses the same classes as every other color.

A role only exists on the properties it's meant for: `bg-accent-soft` works, `text-accent-soft` doesn't. `--ui-accent` itself works with any color utility.

The accent utilities work in your own markup too. Set `--ui-accent` through a class to pick the color:

```vue
<template>
  <div class="[--ui-accent:var(--ui-error)] bg-accent-soft text-accent-default">
    Something went wrong
  </div>
</template>
```

The same class recolors a component outside its `color` prop, like `<UButton class="[--ui-accent:var(--color-indigo-500)]" />`.

::warning
The roles key on that exact `[--ui-accent:…]` class. A scope written with `!` (`![--ui-accent:…]`), a variant prefix (`hover:`, `md:`) or an inline `style` changes `--ui-accent` but keeps the roles of the component's own color, so a neutral soft, outline, subtle, ghost or link component, whose roles point at the neutral tokens, ignores it, apart from what reads the color itself, the focus outline and ring.
::

::note
A few parts set their own `--ui-accent` and take it through `ui` instead: items with their own color in DropdownMenu and ContextMenu, the segments of a ProgressGroup, the links of a NavigationMenu, the loading bar of a Table (`loading-color`), the indicator of a Timeline and the dot of a Chip. Components nested inside keep their own color too, like the buttons of an InputNumber.
::

## Control

Buttons, badges, fields, checkboxes, radio groups and the links of a NavigationMenu write the dimensions of their `size` as variables, and their classes read them:

| Variable | Used for | `md` on a Button |
| --- | --- | --- |
| `--ui-control-px` | Horizontal padding | `--spacing(2.5)` |
| `--ui-control-py` | Vertical padding | `--spacing(1.5)` |
| `--ui-control-gap` | Gap between an icon and the label | `--spacing(1.5)` |
| `--ui-control-icon` | Size of the leading and trailing icons | `--spacing(5)` |

Set them to restyle a size. The room a field makes for an icon is the padding, the icon and the gap added up, and an icon-only button uses the vertical padding on every side, so both follow:

```ts [app.config.ts]
export default defineAppConfig({
  ui: {
    button: {
      variants: {
        size: {
          md: { base: '[--ui-control-px:--spacing(4)] [--ui-control-py:--spacing(2)]' }
        }
      }
    }
  }
})
```

The variables are on the outermost element of the component, which is where the `class` prop lands: the `root` slot of Input, InputNumber, InputMenu, InputTags, Textarea, Checkbox and RadioGroup, and `base` on the other controls. A NavigationMenu writes them on each `link`. On Checkbox and RadioGroup the padding is the one of the `card` and `table` variants.

```vue
<UInput icon="i-lucide-search" class="[--ui-control-icon:--spacing(4)]" />
```

To give a control the same padding on every side, read the vertical one:

```vue
<UButton :label="user.name" :avatar="user.avatar" class="px-(--ui-control-py)" />
```

Slider, Progress, ProgressGroup and Separator write one more variable on their `root`, `--ui-control-thickness`: the height of the track or the width of the line, read as a height or a width depending on `orientation`.

```vue
<UProgress :model-value="50" class="[--ui-control-thickness:--spacing(1.5)]" />
```

Calendar writes `--ui-control-size`, the size of a day cell and the height of a month or year cell, with `--ui-control-px` for the padding of the latter.

::note
A plain padding still wins over the theme: `px-4` on the `base` of an Input replaces its horizontal padding, the room for an icon included.
::

## Radius

`--ui-radius` is the base of Tailwind's `rounded-*` utilities, which Nuxt UI redefines in `@theme`:

```css
@theme default inline {
  --radius-xs: calc(var(--ui-radius) * 0.5);
  --radius-sm: var(--ui-radius);
  --radius-md: calc(var(--ui-radius) * 1.5);
  --radius-lg: calc(var(--ui-radius) * 2);
  --radius-xl: calc(var(--ui-radius) * 3);
  --radius-2xl: calc(var(--ui-radius) * 4);
  --radius-3xl: calc(var(--ui-radius) * 6);
}
```

::warning
Changing `--ui-radius` also affects the `rounded-xs` to `rounded-3xl` classes on your own markup and third-party components, not only Nuxt UI components.
::

## Container

The [Container](/docs/components/container) component takes its max width from `--ui-container`. Point it at another size to change every container at once:

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

@theme {
  --container-8xl: 90rem;
}

:root {
  --ui-container: var(--container-8xl);
}
```

## Header

The [Header](/docs/components/header) component takes its height from `--ui-header-height`. [Main](/docs/components/main) and [Error](/docs/components/error) fill the viewport below it, and [PageAside](/docs/components/page-aside) sticks under it:

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

:root {
  --ui-header-height: --spacing(24);
}
```

## Default CSS

These are the values Nuxt UI ships in `@nuxt/ui/base`. The palettes, aliases and tokens sit in `@layer base` at zero specificity, so the `@nuxt/ui/colors` plugin and your own `:root` rules win over them. The `@theme inline` block of `@nuxt/ui/tailwind` turns each token into its utilities, like `--ui-bg-soft` into `bg-soft`.
