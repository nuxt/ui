Nuxt UI v5 is currently in alpha. Follow the progress in the [v5 tracking issue](https://github.com/nuxt/ui/issues/6918) and share feedback on the [v5 roadmap](https://github.com/nuxt/ui/discussions/6610).

This guide lists the breaking changes from v4 and is updated as the alpha progresses.

## Migrate your project

Update to the latest v5 alpha:

::code-group{sync="pm"}

```bash [pnpm]
pnpm add @nuxt/ui@next
```

```bash [yarn]
yarn add @nuxt/ui@next
```

```bash [npm]
npm install @nuxt/ui@next
```

```bash [bun]
bun add @nuxt/ui@next
```

::

## Changes from v4

### Optional peer dependencies

The dependencies of the [`Editor`](/docs/components/editor), [`Carousel`](/docs/components/carousel) and [`Table`](/docs/components/table) components are no longer installed with Nuxt UI. They are optional peer dependencies, so projects that don't use these components no longer download them.

### Variants engine

Nuxt UI no longer depends on [Tailwind Variants](https://www.tailwind-variants.org/). Components are styled by an engine that ships with the library, with the same API: `base`, `slots`, `variants`, `compoundVariants` and `defaultVariants` behave as before, and every theme in Nuxt UI resolves to the same classes.

Your themes, your `app.config.ui` and your `:ui` overrides keep working untouched. What follows only matters if you use `tailwind-variants` directly, or rely on one of the edge cases listed at the end.

If you import `tailwind-variants` in your own code, it is no longer installed for you:

::code-group{sync="pm"}

```bash [pnpm]
pnpm add tailwind-variants
```

```bash [yarn]
yarn add tailwind-variants
```

```bash [npm]
npm install tailwind-variants
```

```bash [bun]
bun add tailwind-variants
```

::

If you import its types, `@nuxt/ui` exports its own for the surface the engine supports: `ClassValue`, `ClassProp`, `TVVariants`, `TVCompoundVariants`, `TVDefaultVariants`, `TVProps`, `TVReturnType`, `TVSlots` and `VariantProps`:

```diff
-import type { ClassValue, VariantProps } from 'tailwind-variants'
+import type { ClassValue, VariantProps } from '@nuxt/ui'
```

The config type is renamed, since `TVConfig` already means something else in Nuxt UI (the shape of `app.config.ui`):

```diff
-import type { TVConfig } from 'tailwind-variants'
+import type { TVMergeConfig } from '@nuxt/ui'
```

Some generics take fewer type arguments, since the ones they carried were unused: `TVVariants<S, B, EV>` drops its fourth, `TVCompoundVariants<V, S, B, EV>` its fifth, `TVDefaultVariants<V, EV>` and `TVProps<V, EV>` keep only their first and third. Types with no equivalent, such as `TVCompoundSlots` or `TVLite`, describe features the engine doesn't have.

::note
Neither change can be applied by a find and replace: `TVConfig` is a valid Nuxt UI type too, so only imports coming from `tailwind-variants` should change, and the argument lists have to be read one by one.
::

The engine leaves out two things `tailwind-variants` accepted, neither of which any Nuxt UI theme uses:

- `compoundSlots`. A theme that declares it loses those classes silently, since nothing reads the key. Move each entry to a per-slot `class` object in `compoundVariants`, or to the slots themselves when it had no condition.
- The second `config` argument of `tv()`. `app.config.ui.tv` is the one place to configure merging.

Four edge cases resolve differently, each one where `tailwind-variants` produced classes that were never meant. None of them can be found by a find and replace, so check `app.config.ui` overrides that mix value shapes:

- In a slotted theme, an array as a variant value or as a compound `class` now applies to `base`, where it used to be dropped.
- A plain class value set over a per-slot object, such as `variants.size.md = 'text-lg'` over a theme's `{ base, label }`, now merges into `base`, where it used to resolve to `[object Object] text-lg`.
- In a slotless theme, a per-slot object as a variant value now resolves to its `base` entry, where its keys used to be emitted as classes.
- A `(defaults) => classes` replacer on a slot with no classes now receives `''`, where it used to receive `undefined` and could emit the class `undefined`. Under `theme.unstyled` this means the replacer runs where it used to be skipped.
