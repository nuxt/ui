## Usage

Nuxt UI adds its config to the one [`@nuxt/eslint`](https://eslint.nuxt.com) generates. It is built on [`eslint-plugin-better-tailwindcss`](https://github.com/schoero/eslint-plugin-better-tailwindcss) and reads your stylesheet, so it knows the semantic tokens, your color aliases and your own `@theme`.

### Setup

Install the plugin next to `@nuxt/eslint`:

::code-group{sync="pm"}

```bash [pnpm]
pnpm add -D eslint-plugin-better-tailwindcss
```

```bash [yarn]
yarn add -D eslint-plugin-better-tailwindcss
```

```bash [npm]
npm install -D eslint-plugin-better-tailwindcss
```

```bash [bun]
bun add -D eslint-plugin-better-tailwindcss
```

::

That's it, the config is added as soon as both packages are installed. The stylesheet of `css` that imports Tailwind CSS is used as the entry point.

You can turn it off with the `ui.eslint` option in your `nuxt.config.ts`:

```ts [nuxt.config.ts] {4-6}
export default defineNuxtConfig({
  modules: ['@nuxt/eslint', '@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    eslint: false
  }
})
```

::note
If your `eslint.config.mjs` already registers `eslint-plugin-better-tailwindcss`, the config isn't added and yours is left as it is. Remove your setup to use this one instead, both at once make ESLint fail. When the plugin comes from a shared config you import, it can't be detected: set `ui.eslint: false` to keep it.
::

### Rules

The classes are checked in `class` attributes, `:ui` objects, the `:ui`, `:variants` and `:props` of `<UTheme>` and the `ui` of your `app.config.ts`.

| Rule | Default | Description |
| --- | --- | --- |
| `no-palette-colors` | `warn` | Raw palette colors and hardcoded colors. `text-gray-500` suggests a semantic token like `text-muted`, `bg-red-500` suggests `bg-error` when `error` points at `red`. |
| `no-conflicting-classes` | `warn` | Classes that set the same property in the same list, like `p-2 p-4`. The stylesheet order decides which one wins, not the order you wrote them in. |
| `no-unknown-classes` | `off` | Classes your stylesheet doesn't generate. Classes styled in a `<style>` block or your own CSS are unknown too, list them in `ignore`. |
| `enforce-logical-properties` | `off` | Physical classes on the inline axis like `ml-2` or `text-left`, for apps that support [RTL](/docs/getting-started/integrations/i18n/nuxt#dynamic-direction). |

::note
`no-palette-colors` and `no-conflicting-classes` have no autofix, the right token or the class to keep depends on what you meant. `enforce-logical-properties` rewrites each class to its logical name.
::

### Configuration

Pass an object to `ui.eslint` to change the severity of a rule or to ignore classes:

```ts [nuxt.config.ts] {4-11}
export default defineNuxtConfig({
  modules: ['@nuxt/eslint', '@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    eslint: {
      ignore: ['^prose-'],
      rules: {
        'no-unknown-classes': 'warn',
        'no-palette-colors': 'error'
      }
    }
  }
})
```

| Option | Description |
| --- | --- |
| `entryPoint` | The stylesheet that imports `tailwindcss` and `@nuxt/ui`. Defaults to the one found in `css`. |
| `files` | The files to lint. Defaults to `.vue` and script files. |
| `colors` | The palette each color alias points at, `{ error: 'red' }`. Read from the `@plugin "@nuxt/ui/colors"` block of `entryPoint` by default. |
| `ignore` | Classes `no-unknown-classes` leaves alone, as regular expressions. |
| `rules` | The severity of each rule: `off`, `warn` or `error`. |
