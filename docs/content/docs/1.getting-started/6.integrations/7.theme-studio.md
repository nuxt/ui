The Theme Studio layer is **experimental**. Its API may change, and it is not yet published to npm — it currently lives in the `nuxt/ui` monorepo as the `@nuxt/ui-theme-studio` workspace package.
::

## Usage

The [Theme Studio](/theme) — the live theme editor powering this documentation — is available as a [Nuxt layer](https://nuxt.com/docs/getting-started/layers) so any Nuxt UI app can embed it. Extend the layer in your `nuxt.config.ts`:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: ['@nuxt/ui-theme-studio'],

  modules: ['@nuxt/ui']
})
```

Then import the studio's stylesheet in your Tailwind entry file, after `@nuxt/ui`:

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";
@import "@nuxt/ui-theme-studio/theme.css";
```

::note
The stylesheet must be imported at CSS **build time** — it redefines `@theme` tokens (the shadow ramp, default border widths) that Tailwind compiles utilities from, so it can't be injected at runtime. Everything else — restoring the persisted theme, first-paint FOUC prevention, the `<style>` tags carrying the applied theme — is wired automatically by the layer's plugin.
::

The studio adopts **your app's existing theme as its baseline**: colors and icons are read live from your `app.config.ts`, and the radius, font, base size and spacing controls start from your stylesheet's computed values. Untouched settings emit no overrides — your CSS stays in charge until a value actually changes — and **Reset** returns to your app's look, not to Nuxt UI's stock theme.

### Components

Drop the [ThemeStudioButton](#themestudiobutton) component anywhere in your app — a header, a toolbar, next to your `UColorModeButton`:

```vue [app/app.vue]
<template>
  <ThemeStudioButton />
</template>
```

It opens the full editor in a popover: theme presets, color pickers with per-shade control, typography and layout settings, style options like shadows and borders, plus reset and import/export.

## ThemeStudioButton

Everything is optional and prop-driven, because there are really two audiences for an embedded editor:

- **You, the developer** — theming your own app with the full studio: palette curves, per-token shades, semantic aliases, export to CSS. This is the default, `mode="dev"`.
- **Your users** — personalizing their account or workspace inside your product. They should get a curated picker — approved presets, colors as a plain dropdown, maybe typography — not palette surgery or a CSS export of your design system. That's `mode="user"`.

### Modes

`mode="user"` turns off the power-user affordances in one move: the palette curve editor, the per-token shade sliders, the Semantic alias section, the typographic controls (weight, case, tracking, leading), the per-component defaults, the sizing knobs, the Style panel and import/export. What's left is what an end user actually reaches for — presets, colors as simple swatch dropdowns, font families, icons, radius and a light/dark switch. Combined with a restricted preset list, this is the realistic end-user setup — think a SaaS letting members pick an approved look for their workspace:

Each affordance `mode` flips is also a key on the `features` prop, so you can compose your own level between the two:

| `features` key | What it controls | `dev` | `user` |
| -------------- | ---------------- | ----- | ------ |
| `palette` | The palette curve editor on each color | ✅ | ❌ |
| `shades` | Per-token shade sliders (colors and style panels) | ✅ | ❌ |
| `semantic` | The Semantic alias section (`success`, `warning`, …) | ✅ | ❌ |
| `typography` | Weight, case, tracking and leading — the font pickers always stay | ✅ | ❌ |
| `components` | Button/Card/Input Defaults (variant and color) | ✅ | ❌ |
| `scale` | Base font size, spacing density and default size — radius always stays | ✅ | ❌ |
| `help` | Section-header links into these docs | ❌ | ❌ |

The remaining props are separate, since they shape the panel rather than gate a control:

| Prop | What it controls | `dev` | `user` |
| ---- | ---------------- | ----- | ------ |
| `panels` | Which control panels to offer, in order | colors, general, style | colors, general |
| `share` | Theme import/export | ✅ | ❌ |
| `reset` | Reset — the header button and every section's reset-to-preset | ✅ | ✅ |
| `colorMode` | A light/dark switch in the header | ❌ | ✅ |
| `title` | Heading above the panels | — | — |

```vue
<template>
  <!-- a dev editor without export, or a user editor that keeps shades -->
  <ThemeStudioButton :share="false" />
  <ThemeStudioButton mode="user" :features="{ shades: true }" />
</template>
```

### Presets

Restrict the preset list to specific ids, or hide the panel entirely with `false`:

```vue
<template>
  <!-- only these two presets -->
  <ThemeStudioButton :presets="['nuxt-ui', 'shadcn']" />

  <!-- no presets panel at all -->
  <ThemeStudioButton :presets="false" />
</template>
```

Provide your own presets with `custom-presets` — they are appended after the stock list. A preset is a name, an icon and a [ThemeDoc]{class="font-mono"} describing the theme:

```vue
<script setup lang="ts">
import type { ThemePreset } from '@nuxt/ui-theme-studio/engine'

const brand: ThemePreset[] = [{
  id: 'acme',
  name: 'Acme',
  description: 'The Acme brand theme',
  icon: 'i-lucide-rocket',
  doc: {
    version: 1,
    colors: { primary: 'indigo', neutral: 'zinc' },
    font: { sans: 'Inter' },
    radius: 0.5
  }
}]
</script>

<template>
  <ThemeStudioButton :custom-presets="brand" />
</template>
```

### Panels

Choose which control panels to offer with `panels` — any of `colors`, `general` and `style`, in the order you want them:

```vue
<template>
  <!-- colors only, no typography/layout or style panels -->
  <ThemeStudioButton :panels="['colors']" />
</template>
```

### Header

The header carries an optional `title`, a light/dark switch (`colorMode`, on by default in `user` mode) and the reset and import/export buttons. It disappears entirely when nothing is left to put in it:

```vue
<template>
  <ThemeStudioButton mode="user" title="Customise Theme" />

  <!-- no header: no title, and every action turned off -->
  <ThemeStudioButton :color-mode="false" :share="false" :reset="false" />
</template>
```

### Saving to account data

Local persistence is automatic — every edit lands in `localStorage` and survives reloads. To make a user's theme follow them across devices, listen to the `change` event (the full [ThemeDoc]{class="font-mono"} on every edit) and apply the saved doc back on load:

```vue [app/components/AccountTheme.vue]
<script setup lang="ts">
const { applyDoc } = useThemeStudio()

// restore the account's saved theme once on load
const { data: saved } = await useFetch('/api/me/theme')
onMounted(() => saved.value && applyDoc(saved.value))

// persist every edit — debounce to taste
const save = useDebounceFn((doc: any) => $fetch('/api/me/theme', { method: 'PUT', body: doc }), 500)
</script>

<template>
  <ThemeStudioButton mode="user" @change="save" />
</template>
```

## Composables

The layer's composables are auto-imported, so you can also build your own controls:

- `useThemeStudio()` — the editing surface: `presets`, `activePreset`, `applyPreset(preset)`, `shuffle()`, the current `style` document and `setStyle(patch)` for granular edits.
- `useTheme()` — the applied theme: the current `color`, `radius`, `font` and `mode` settings with their setters, `hasCSSChanges`/`hasConfigChanges` dirty flags, `resetTheme()`, and `themeDoc` — the reactive [ThemeDoc]{class="font-mono"} behind the button's `change` event.

```vue [RandomThemeButton.vue]
<script setup lang="ts">
const { shuffle } = useThemeStudio()
</script>

<template>
  <UButton label="Surprise me" icon="i-lucide-dices" @click="shuffle()" />
</template>
```

## Analytics

The layer ships a no-op `useAnalytics()` that the studio calls with events like `Theme Preset Applied`. Define your own composable of the same name in your app to receive them — the app's declaration wins over the layer's:

```ts [app/composables/useAnalytics.ts]
export function useAnalytics() {
  return {
    track(event: string, properties?: Record<string, any>) {
      // forward to your analytics of choice
    }
  }
}
```
